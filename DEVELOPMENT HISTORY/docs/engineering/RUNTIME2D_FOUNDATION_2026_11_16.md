# LUNA Runtime2D: стартовый технический каркас

**Состояние после консолидации:** исходный 2D-стенд перенесён в [game/](../../game/README.md). Документ описывает возможности исходной ревизии. Утверждённые локации, игровой арт и полноценный HUD ещё предстоит подключить.

## Запуск

Откройте `game/project.godot` в Godot 4.3+. Точка входа внутри проекта — `scenes/runtime2d/sandbox.tscn`. Комнаты `DEV_SANDBOX_A` и `DEV_SANDBOX_B` нужны для технической проверки переходов.

Тест: `godot --headless --path . --script res://tests/test_runtime2d_foundation.gd`. Проверку запуска и выполнение теста дополнительно выполняет GitHub Actions.

### Диагностические клавиши

| Клавиша | Только в прототипе |
| --- | --- |
| WASD / стрелки | Ходьба по двум осям |
| F2 | Открыть/закрыть глаза (состояние наблюдателя; без готовых пазлов) |
| F3 | Войти в физически близкую тестовую дверь |
| F4 | Положить/поднять палочку рядом с Луной |
| F5 | Клонировать тестовую Entity |
| F6 / F9 | Сохранить / загрузить отдельный V2-сейв |
| F8 / Shift+F8 | Записать / восстановить последний снимок |
| F10 | Переключить FOLLOW/LOCKED |

**E оставлена под заклинание, TAB под взлом**, согласно авторским решениям 13.11. Клавиши F2–F10 являются тестовыми, не закрепляют финальное управление. HUD проекта разрабатывается независимо и здесь отсутствует полностью. Отладка идёт через клавиатурные команды и тесты, без наложенных поверх мира меток. После завершения UI он сможет подключиться отдельной CanvasLayer, подписавшись на `location_entered` и `perception_changed`.

## Модули и контракты

- `ActorBody2D`: реальный `CharacterBody2D`, стабильный Entity ID, `EntityRecord` и `ParameterRegistry` из существующего ядра, `CommandProcessor` с Undo. Изменение MOVE_SPEED влияет на ходьбу, SCALE на физический радиус и VisualAnchor, IS_ALIVE и AI_ENABLED на движение; `BehaviorBrain2D` добавляет IDLE/WANDER/FOLLOW/CHASE/FLEE/AUTO. Сложный 3D-AI с маршрутизацией и реакциями NPC ещё не портирован целиком. Рисуется только нейтральный технический маркер без конечностей; в `VisualAnchor` можно вставить `PackedScene` с утверждённым pixel-art.
- `LevelShell2D`: раздельные фон, коллизии, сущности, эффекты. Две прозрачные или непрозрачные фоновые пластины с общими размерами/координатами. Переключение никак не меняет физическую геометрию. Пока пластины не готовы, отображается тестовая сетка; **не** обещана окончательная неоновая изнанка.
- `ProjectionField2D`: обычный мир отображается всегда, когда палочка у Луны (даже при другом ACTIVE TOOL); после оставления палочки обычный мир сохраняется в радиусе, за ним видна изнанка. Радиус 320 px является временным числом тестового рантайма, не художественным решением.
- `CameraFollowLock2D`: только FOLLOW и LOCKED. Невидимые на экране объекты в текущем мире продолжают физическую симуляцию. `contains_world_point()` даёт геометрию экрана, но ещё не решает перекрытия, реакцию существ на взгляд и метамост.
- `LocationRouter2D`: реестр адрес → PackedScene + точка появления, реальные редактируемые адреса дверей, отдельные проверки уровня доступа палочки и персонажа. Нет географии Этернии, не вводится взлом названия уровня или поле телепорта в мини-карте. Каждый будущий авторский ID регистрируется только после утверждения карты.
- `AccessState2D`: раздельные PLAYFUL/DEVELOPER палочки и системный доступ аватара. Открытые значения доступны в API, самовзлом/GUI ещё не собраны.
- `SaveStore2D`: отдельный JSON V2 с временным файлом и заменой; старые V1/3D сохранения не читаются. Перед восстановлением проверяются структура, ID комнат, позиции, доступы и сущности; rollback возвращает согласованные Entity/двери/камеру/палочку. Добавлена ограниченная история `WorldTimeline2D` для будущего безопасного отката с неоткатываемым защитным таймером. Полный физический replay будущих сервисов остаётся отдельной задачей.

### Интеграционные точки для параллельного арта/UI

1. Арт-агент поставляет пару фоновых изображений с **одинаковым размером, происхождением и геометрией**. `LevelShell2D.set_background_pair()` отказывает при несовпадении размеров. Обе пластины должны оставаться **неинтерактивным фоном**.
2. Геометрия Google Sheets/SAI превращается в реальные `CollisionShape2D` в `AuthoredCollision`. Неизвестные ещё координаты не выдуманы.
3. Луна/NPC/объекты получают отдельные визуальные `PackedScene`, присоединяемые через `ActorBody2D.attach_visual()`. Клонирование копирует игровые данные, а не дублирует одну декоративную картинку.
4. После готовности отдельной UI-ветки интерфейс подключается самостоятельной CanvasLayer. Для близкого взлома TAB используйте `request_wand_parameter_edit`, не доверенный `set_entity_parameter`, который пока предназначен лишь для авторского кода и тестов. Другие игровые действия подключаются после согласования их прав доступа. В текущем прототипе не создаются HUD, мини-карта, overlay и панели. Имеющиеся старые 3D `SaveService`, `WorldAccessService` и пространственные селекторы используют `Node3D/Vector3` и потому **ещё не портированы**.

## Что пока сознательно не сделано

Полный набор 17 утверждённых артефактов, рецепты зелий, индивидуальные параметры NPC, программирование заклинаний, перенос AI из 3D, управляемый GAME_FRAME и виртуальный рабочий стол, полноценная физическая мини-карта и инвентарь, девять комнат, реакция моста на взгляд игрока, перемотка Кнопкой времени, безопасные лимиты всех возможных эксплойтов. Для них созданы совместимые базовые точки интеграции; `FLY`, `GLOW` и `REGENERATION` уже имеют реальные адаптеры, а физический Банк способностей работает через старые атомарные компоненты. Точная перспектива 3/4 и финальный размер пикселя требуют теста на утверждённом арте.

**Дальнейшая последовательность:** принять 2D-рантайм и физику → подключить новые персонажные спрайты и UI без конфликтов → импортировать один авторский уровень и его коллизии → системные способности и наблюдение → метасекреты. Изменение/удаление старого 3D-кода отдельным PR после переноса зависимых тестов.

**Обновление 16.11:** добавлены независимые физические двери `Doorway2D`, проверенные восстановление в произвольной тестовой комнате, базовый AI, реальные адаптеры FLY/GLOW/REGENERATION, ограниченный `WorldTimeline2D` и политика ближнего взлома без интерфейса. Подробный актуальный контракт: `docs/engineering/RUNTIME2D_WORLD_CONTRACT_V1.md`.
