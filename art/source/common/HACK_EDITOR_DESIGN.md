# Окно взлома: предложение для обсуждения

Рамка и контролы собираются из отдельных ассетов. Имена, ID, числа, технические значения и подсказки рисует Godot. Верх: имя Entity и постоянный ID. Слева: слот превью, исходный TYPE, роли и теги. Справа: категория и прокручиваемые строки параметров. Нижний ряд COPY / DELETE / DONE постоянно доступен. Прокручивается только содержимое, а не заголовок и действия.

## Контролы

- Число: прямой ввод и шаговые кнопки; ползунок для понятного ограниченного диапазона. Шаг и пределы поступают из ParameterRegistry.
- Boolean: два явно подписанных состояния TRUE и FALSE.
- Enum: раскрываемый список допустимых значений.
- Цвет: образец и выбор допустимого цвета; произвольный picker требует поддержки игровой моделью.
- Ссылка Entity: будущий выбор цели через постоянный ID, а не произвольное имя.
- Теги и способности: отдельный список элементов и пустое состояние; нужен отдельный UI поверх существующих сервисов.

## Поведение

Существующий редактор применяет изменения сразу через CommandProcessor. DONE закрывает окно и продолжает игру. Ошибка ввода должна оставлять прежнее допустимое значение в мире и показывать причину рядом с полем. Незаконченный текст числового поля не отправляется в сервис. Перетаскивание ползунка объединяется в один жест Undo.

Технические имена остаются английскими. Подсказка по hover/focus содержит локализованное название и черновую реплику Луны. Макет в чате выводит пояснение снизу для обсуждения; это не утверждённый постоянный блок финального окна.

Десять категорий уже заданы в HackEditor. Для компактной панели предлагаются значки с подписью активной категории, доступными полными названиями и навигацией по всем категориям. Не ужимать десять длинных названий в нечитаемый ряд. В макете временно показаны все названия словами для обсуждения состава. Пустая категория объясняет отсутствие данных.

## Кики и границы реализации

Для Кики используется то же окно. DELETE должен вызывать принятое игровое поведение: исчезновение на секунду и возвращение со стандартными настройками. Это требует дополнения lifecycle/save/undo и пока не реализовано. UI должен обращаться к реальному сервису, а не изображать сброс только визуальным таймером.

Подготовлены графика и демонстрационный макет с иллюстративными значениями. Макет не подключён к миру Godot. Существующий HackEditor ещё не переработан под этот дизайн. Наличие вкладок и ассетов не означает готовность соответствующих игровых механик.
