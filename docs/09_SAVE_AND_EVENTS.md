## Реализовано

**EventBus** доставляет типизированные события через очередь с ограничением глубины (6) и работы за кадр (48). **RuleEngine** разбирает события и выполняет правила WHEN → IF → DO → TARGET. **EffectEngine** применяет SET, ADD, MULTIPLY, TOGGLE через CommandProcessor — общий механизм изменений для взлома и будущих заклинаний.

В игровом прототипе есть демо: холодильник с режимом CHASE и целью TREE при обнаружении дерева автоматически перекрашивает дерево в розовый. Пока нет редактора правил для игрока; это проверка архитектуры.

## SaveService и управление

- **F6** — сохранить мир вручную.
- **F9** — загрузить последнее сохранение.
- **Каждые 30 секунд** при активном игровом мире — автосохранение.
- При нормальном закрытии игры — сохранение; при новом запуске — автоматическая загрузка.

Файл: `user://luna_world_v1.json` в пользовательской папке Godot (не в GitHub).

Сохраняются позиции Луны и редактируемых объектов, исходные категории, параметры, цвет, живость и поведение. Brain после восстановления начинает с новой краткосрочной цели. Открытия игрока, заклинания, журнал Юки, историю команд и переходы между мирами пока **не сохраняем**. Отдельной системы перков нет и не планируется. Позже профиль и знания должны храниться отдельно от текущего забега.

JSON имеет номер версии и типизированные цвета. SaveService сначала проверяет весь снимок, затем применяет данные; пишет во временный файл и заменяет основной. Некорректный JSON или тип параметра не должен ломать текущую сцену. Ближайший этап: резервные копии, миграции формата, несколько слотов и общий профиль.

## Новая дисциплина UI

По решению автора из инспектора взлома убраны **UNDO/REDO и технический CHANGE_HISTORY**. Внутренний CommandProcessor остаётся доступен коду. SHOW_HINTS показывает короткие ироничные фразы Луны, например: «Оживляет объект. Или делает неживым, тут как повезёт».

Новая компоновка окна поверх RPG (снизу справа) и 2D-переходы сохранены как планы на будущее, без преждевременной переделки UI.
