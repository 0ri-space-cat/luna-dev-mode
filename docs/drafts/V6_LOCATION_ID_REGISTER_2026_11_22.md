# V6 — единый черновой реестр пространственных адресов и системных имён

> **Прямое авторское изменение 22.11:** [глава 36](../canon/36_V6_AUTHOR_KNOWLEDGE_WALL_UNDERSIDE_DESKTOP_AUTONOMY_2026_11_22.md). `META_WHITE_VOID` — настоящий адресуемый LOCATION ID, доступный через TELEPORT в универсальной лесной консоли и `TARGET_LOCATION` совместимой двери. `GAME_MODE` — системный enum `FULLSCREEN/WINDOWED`, WINDOWED означает внутриигровую композицию виртуального desktop; старый глобальный пароль `SIMULATION_BOUNDARY` **отменён**, не создавать его в реестре.

> **Финальное закрепление 22.11:** крупные адреса из [библии 35](../canon/35_LUNA_V6_FINAL_GAME_BIBLE_FOR_IMPLEMENTATION_2026_11_22.md) и [инженерной спецификации](../engineering/LUNA_V6_FINAL_IMPLEMENTATION_CONTRACT_2026_11_22.md) теперь production-design ID. Прежние пометки CANDIDATE для перечисленных основных локаций и глобальной пары были историческими. Малые поляны без самостоятельной загрузки остаются подзонами, а не неразрешённым художественным выбором.

**Дата:** 22 ноября 2026. **Статус:** сценарная согласовательная таблица, а не доказательство, что каждый адрес уже реализован в Godot. [Канон и статусы](../canon/34_V6_AUTHOR_RESPONSE_TO_NINE_CHAPTER_AUDIT_2026_11_22.md); [сквозной аудит](../audits/2026-11-22_V6_FULL_WORLD_TONE_SECRET_GAMEPLAY_AUDIT.md). Каждый физический регион требует проверки по реальному world.json/сцене при сборке. Старая цифра **46 строк** в аудите означала количество встречавшихся в тексте разных токенов, в том числе префиксов, а не утверждение 46 готовых уровней.

**Новое различие 22.11: FEATURE_ID vs LOCATION_ID для множества повторяемых тайных мостов и проходов.** [38](../canon/38_V6_FOREGROUND_OCCLUSION_DISCOVERY_LAYER_2026_11_22.md) определяет проходимые ordinary foreground-карманы, а [39](../canon/39_V6_REPEATED_WORLD_SECRET_LAWS_DISTRIBUTION_2026_11_22.md) перечисляет **5 изнаночных проходов, 16 мостов четырёх видов, 4 изнаночные двери и 4 двери закрытых глаз** в нескольких регионах. **Большинство новых строк в 39 являются FEATURE_ID, а не настоящими загружаемыми локациями**, поэтому не добавлять их автоматически в список `LOCATION_ID` без самостоятельной сцены. Исторически ранее утверждённое `ET_CRYSTAL_UNDERSIDE_PASSAGE` остаётся отдельно зарегистрированным **Location ID**, а `UNDERSIDE_MOUNTAIN_CLIFF_SEAM` и другие новые примеры являются объектами/особенностями уже существующей локации до уточнения реальной карты. Никакого отдельного сюжетного флага у повторных мостов.

## Типы имён

- **LOCATION_ID:** строка настоящего адресуемого региона, включая **ET_* и META_***, если в реестре задан safe spawn/ReturnAnchor. Возникает в HUD при реальном входе даже в Белую Пустоту; обычная непрерывная подзона не показывает ID каждые несколько шагов.
- **FEATURE_ID / BEHAVIOR:** имя объекта, физического закона или водного источника **внутри** локации, не новый адрес сам по себе.
- **SYSTEM_TARGET / SYSTEM_PROPERTY:** объект или параметр уровня игры, например `GAME_FRAME`, `GAME_MODE`, `OUTSIDE_COLLISION`. Их **нельзя путать с Location ID**; но настоящий `META_WHITE_VOID` является адресом совместимой двери, а не системным значением переключателя.
- **CANDIDATE:** полезная рабочая строка из сценария, не объявленная автором окончательной и не гарантированно существующая в коде.

## Важные инварианты для кодового реестра

1. Один настоящий ID должен указывать на **одну определённую логическую сцену**; переиспользование одного вида стен для двух разных мест не означает общий ID.
2. При входе через адресную дверь нужен **действительный ReturnAnchor** и безопасная точка назначения. Нельзя появиться в потоке водопада, пустой коллизии, бесконечном падении или теле клона.
3. Раннее знание любого настоящего Location ID, включая `META_WHITE_VOID`, не требует сюжетного флага или первого визита. Валидатор проверяет **существование, тип Location ID и безопасную точку перехода**, не запрещает весь префикс META_.
4. Большая карта и Пиксельный глобус показывают доступную картографию, не автоматически все скрытые узлы и их внутренние адреса.
5. Первый вход в настоящую новую сцену показывает ID внизу HUD, повторный вход тоже; непрерывное движение внутри одного ID не вызывает десяток плашек.
6. **Что остаётся задачей реализации:** точные PackedScene Godot, геометрия изнаночного прохода и мостов, SafeSpawn/ReturnAnchor, рендер виртуального desktop, точки рождения клонов и безопасное возвращение от водопада. **Никакого специального глобального переключателя леса не нужно.**

## Быстрая приёмка

- Поиск по активным сценариям не должен показывать ET_WATERFALL_BEYOND_THIRD_BRIDGE как актуальный ID.
- При входе в пещерное Озеро HUD показывает ET_DUPLICATE_LAKE_CAVERN, а не ET_DUPLICATE_LAKE.
- Чёрный загрузочный карман не называется Белой Пустотой.
- Лесной терминал выполняет `TELEPORT META_WHITE_VOID` **по настоящему знанию даже с PLAYFUL**; ID показан при входе в Пустоту, но не требуется флаг её посещения.
- `GAME_MODE=WINDOWED` рендерит виртуальный desktop; рамка открывается `OUTSIDE_COLLISION=PASSABLE` посредством DEVELOPER-взлома или известной системной команды леса. Один выбор WINDOWED не запускает финал.
- Совместимая дверь принимает `TARGET_LOCATION=META_WHITE_VOID` и не создаёт копии NPC, не размножает уникальные инструменты, сохраняет возвращение и нормальные ID.
