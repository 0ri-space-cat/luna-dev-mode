# 07 — Первая играбельная версия (Godot graybox 0.2)

## Что добавлено

Это **самый первый технический прототип**, созданный для проверки петли «выбрать объект → остановить мир → изменить параметры → наблюдать последствия». Он не является реализацией всей архитектуры из docs/05.

- Минимальный проект Godot 4.3+ в режиме GL Compatibility для проверки на Mac.
- Ортографическая 3D-камера сверху под углом; пастельные цвета и примитивные фигуры.
- Луна — процедурный placeholder с шляпой; перемещается по WASD или стрелкам.
- Два дерева и холодильник; выбираются кликом мыши посредством физического луча.
- Универсальный реестр определений и редактор **шести параметров** с английскими именами капсом: `IS_ALIVE`, `AI_ENABLED`, `HEALTH`, `MOVE_SPEED`, `SCALE`, `BASE_COLOR`. Значения логических полей отображаются как `TRUE/FALSE`.
- Поля UI генерируются из `ParameterRegistry`; диапазоны, подсказки, значения по умолчанию и типы хранятся в одном месте. Есть возможность добавлять параметры, доступные только определённым категориям.
- `CommandProcessor` записывает источник изменения (`luna / wand:luna` сейчас, позже Юки/правила/заклинания), историю операций и поддерживает **Undo/Redo**. Перетаскивание ползунка группируется в одно отменяемое изменение.
- Мир замирает во время редактирования (SceneTree.paused); появляется лёгкая бирюзовая пелена. UI продолжает работать. Полный глитч и звук — позже.
- `SHOW_HINTS: TRUE/FALSE` включает или скрывает короткие русские пояснения под каждой строкой параметра; изначально подсказки выключены.
- `IS_ALIVE: TRUE` показывает ноги и запускает самостоятельное случайное движение. Дерево тоже можно оживить.
- `AI_ENABLED: FALSE` прекращает автономное блуждание, не отменяя жизнь.
- Скорость Луны увеличена с `5.0` до `7.5` единицы/сек, добавлено быстрое ускорение и замедление.
- Простая модель EntityRecord хранит исходную категорию и набор значений, не привязанный к оформлению.

**Не реализовано:** сохранение истории и изменений на диск, полноценные транзакции нескольких объектов, работающие NPC, правила, заклинания, артефакты, перки, мета-секреты, порталы, пользовательские гравировки и финальная графика. Нынешний `CommandProcessor` и реестр — фундамент для этих систем, а не их завершённая реализация. Они описаны в docs/01–06 и не должны считаться забытыми.

## Запуск на macOS

1. Установить Godot 4.3 или новее, если он ещё не установлен. Исходники проекта не требуют плагинов и сторонних 3D-ассетов.
2. Скачать репозиторий (Code → Download ZIP) или выполнить команду клонирования: git clone https://github.com/0ri-space-cat/luna-dev-mode.git.
3. В Godot Project Manager выбрать Import → файл project.godot из папки репозитория.
4. Открыть проект и нажать F5 (Play Project).
5. Ходить WASD/стрелками. Кликнуть по дереву или холодильнику. В редакторе менять `BASE_COLOR`/`SCALE`/`HEALTH`/`MOVE_SPEED` и установить `IS_ALIVE: TRUE`. Можно отдельно выключить `AI_ENABLED`, чтобы оставить объект живым, но неподвижным. Переключатель `SHOW_HINTS` показывает краткие русские описания. Попробовать кнопки `UNDO` и `REDO` или Cmd+Z / Cmd+Shift+Z. Нажать кнопку закрытия или Esc: мир снова движется.

Если нажать ЛКМ на пустом месте, ничего не произойдёт. Редактор предназначен только для тестовых объектов.

## Известные ограничения и проверки

- Код отправлен в GitHub, но **в локальной рабочей среде Godot CLI отсутствует**. Есть отдельный GDScript smoke-тест и GitHub Actions, но реальное поведение UI по-прежнему нужно проверить в Godot на Mac.
- Временная графика: пока без толстых контуров, финальных анимаций, постерного стиля и пиксельного шрифта.
- Ножки сущностей пока простые геометрические прямоугольники.
- **BACKLOG от автора:** холодильник блуждает неохотно и слишком прямыми линиями. В следующей версии поведения добавить мягкие повороты, более выразительную ходьбу, адекватные паузы и реакции на препятствия. Пока алгоритм намеренно не перерабатывался.
- Случайное блуждание ограничено приблизительными координатами площадки и ещё не имеет навигации вокруг препятствий.
- Изменения размера, цвета и скорости происходят немедленно; HP пока демонстрационный параметр без боевой механики.
- Поведение объектов обрабатывается в _physics_process; во время редактора пауза останавливает движения, пока всегда активный CanvasLayer показывает UI.

## Следующие технические шаги

1. Прогнать v0.2 в Godot на Mac и проверить, что история изменения и Undo/Redo работают при смене объектов.
2. Выделить жизненные и поведенческие параметры по компонентам, добавить новые категории в ParameterRegistry.
3. Оживлённым предметам дать универсальные цели (патрулировать / следовать / нападать) и улучшить движения холодильника.
4. Добавить окно правил и короткую цепочку эффектов; затем попробовать «записать взлом как заклинание».
5. Проводить визуальную стилизацию после проверки работающего core loop.

## Тестовый сценарий

- [ ] Godot открывает проект без ошибки парсера.
- [ ] F5 запускает сцену.
- [ ] Луна ходит на WASD/стрелках.
- [ ] ЛКМ на дереве открывает панель.
- [ ] Во время панели Луна/существа не движутся.
- [ ] Цвет и размер выбранного объекта изменяются.
- [ ] `IS_ALIVE: TRUE` заставляет объект двигаться после закрытия панели.
- [ ] `IS_ALIVE: FALSE` останавливает блуждание.
- [ ] `SHOW_HINTS: TRUE` показывает все короткие русские описания; `FALSE` их скрывает.
- [ ] При переключении выбранного объекта значения в окне обновляются и подсказки не сбрасываются.
- [ ] Холодильник сохраняет категорию fridge, дерево — tree.
- [ ] `AI_ENABLED: FALSE` останавливает движение, не выключая `IS_ALIVE`.
- [ ] `UNDO` отменяет последнее изменение; `REDO` возвращает его.
- [ ] Одно перетаскивание ползунка откатывается одним `UNDO`.
- [ ] `CHANGE_HISTORY` показывает идентификатор объекта, поле и автора изменения.
- [ ] Увеличенная скорость Луны комфортна.

## Программные проверки

- Локально с Godot CLI: `godot --headless --path . --script res://tests/test_parameter_system.gd`.
- В GitHub добавлена CI-проверка исходников и этого теста в `.github/workflows/godot-smoke.yml`.
- Проверка покрывает типы и границы значений, независимость экземпляров, права категории, смену автора изменения, Undo/Redo и группировку ползунка.
- Эти проверки не заменяют ручной визуальный запуск GUI и проверку поведения в 3D.
