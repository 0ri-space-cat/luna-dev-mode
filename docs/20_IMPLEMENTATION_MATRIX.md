# 20 — Карта реализации игрового мануала и порядок разработки

**Актуально:** ноябрь 2026, после технического среза 0.19. **Назначение:** предотвратить потерю заявленных возможностей и не путать описанную игру с доступным прототипом. Этот список — карта зависимостей, а не обещание реализовать всё одним релизом. Первоисточники — docs/01–06, новые решения — docs/18–19.

## Точка отсчёта: что есть в коде

| Подсистема | Состояние | Ограничение |
| --- | --- | --- |
| ParameterRegistry, EntityRecord | Рабочее ядро 0.20 | Категория неизменна; базовые роли и теги реализованы, расширяемые компоненты и сценарные фракции впереди |
| CommandProcessor, атомарные изменения, Undo/Redo и provenance | Рабочее ядро | История пока в памяти; общий API удаления/восстановления сущности не закончен |
| EventBus и EffectEngine | Рабочее ядро | События и эффекты пока покрывают ограниченный набор операций |
| RuleEngine: WHEN / IF / DO / TARGET | Улучшено в 0.19 | Составные AND/OR/NOT, приоритеты, квоты и сохранения; без редактора игрока и contact/zone/timer событий |
| Оживление и универсальный BehaviorBrain | Рабочий graybox | Без полной анатомии, рас, фракций и сложного принятия решений |
| RelationshipService + SocialAwareness | Частично | Направленные отношения, свидетельство вреда/интереса; без полноценной дружбы/доверия, управления фракциями и эмоциями |
| Магия и конструктор блоков CREATE/SHAPE/ELEMENT/BEHAVIOR/RELEASE/ON_HIT | Рабочий graybox | Простые формы и 3 стихии; много доставки/целей/эффектов и гибких условий пока отсутствуют |
| Огонь/лёд/молния, цепи, пар, материалы | Рабочий graybox | Реакции и поля ограничены, полноценная системная физика и погода впереди |
| Сохранения мира, профиль знаний, собственные рецепты | Частично | JSON с валидацией, автосохранение; нет полноценной структуры множества сценариев/забегов и миграций |
| Копирование деревьев/холодильников/созданных магией сущностей | Частично | Независимые ID, параметры, роли и теги; ещё нужны lifecycle Undo/Redo, локальные связи и строгие правила удаления |
| Английский/русский UI, hover-подсказки и вкладки | Рабочий начальный UI | Нужна полная локализация всех динамических надписей и финальный визуальный интерфейс |

## Что обязательно довести по творческому мануалу

| Система | Текущий пробел | Правильная архитектурная опора |
| --- | --- | --- |
| **Entity-композиция** | Роли/теги/компоненты, инвентарь, способности, форма и функциональность отдельно | EntityRecord + каталог компонентов, не переименовывать дерево после оживления |
| **Жизненный цикл** | Создание/клонирование/удаление/восстановление, надёжные ссылки | Команды, WorldRegistry, сериализация; без физической порчи сохранения |
| **События мира** | Касание, вход в зону, получение удара, применение предмета, таймер, изменение адреса | EventBus; универсальные триггеры для RuleEngine |
| **Гибкие селекторы** | Фильтры по роли/тегу, отношениям и радиусу, групповые действия | WorldRegistry + TargetResolver; лимиты на количество целей |
| **AbilityService** | Выдача, кража, копирование, активация способностей | Одинаковая модель для NPC, растения, палочки, магии и артефакта |
| **Инвентарь / артефакты** | Хранение предметов, перенос между мирами и забегами, быстрое использование | Item/Inventory/ArtifactService, без заранее придуманного пользовательского UX |
| **Еда / напитки** | Съедобность, порции, эффекты при употреблении, передача свойств | Тот же EffectEngine, никакого отдельного скрипта на лимонад |
| **Поведенческие системы** | Более естественное блуждание, спутники-защитники, сопротивление взлому | BehaviorBrain/RelationshipService + особенности сущностей, а не 100 AI-скриптов |
| **Фракции, культы и NPC** | Управление союзами, лидерством, диалогами, последствиями действий | Социальный граф, события/отношения/память, сюжетные культы без случайного автоспавна |
| **Эмоции, эмпатия** | Облака настроений с причинами, отдельный мир эмотов/токсиков | Состояния и provenance; без глобального усложнения всех миров |
| **Перки** | Умеренная постоянная прогрессия между забегами | PlayerProfile отдельно от RunState; знания не блокируют механики |
| **Миры и двери** | Сценарии, портальные адреса, перепривязка маршрутов, предметы через переход | WorldManager, адреса и законные пространственные условия |
| **Луна / PLAYER_AVATAR** | Отдельные личность, модель, анатомия, системные права, живая ссылка | AvatarBindingService; ошибки восстанавливаемы без таймера |
| **Юки** | Вторая участница-взломщица, реальные следы чужих команд, находка через расследование | Provenance и детерминированные события, не только сюжетный диалог |
| **Журнал экспериментов** | Автозаметки Луны, гипотезы, идеи, реальные следы наблюдений | ProfileService + EventBus; записи не служат скрытым ключом |
| **Мета: HUD** | Физический доступ при остановке камеры у края карты | Системный объект-представление с реальной привязкой к Луне |
| **Мета: рамка и карта** | Безопасное взаимодействие с окном/адресами, fullscreen-альтернативы | ApplicationShell + WorldManager, без доступа к OS |
| **Нестабильность / пустота** | Игровая перегрузка, управляемое разрушение, физическое меню, запретные области | IntegritySystem/NullSpaceManager и RecoverySnapshots, настоящий FPS не губить |
| **Визуальное производство** | 2.5D леса и города, водопады, пиксельные карточки, инвентарь, глитч | Позже; сейчас только явные контракты с будущими моделями и HUD |

## Порядок зависимостей (без искусственных сюжетных блокировок)

1. **Следующий фундамент:** Entity-компоненты (базовые роли/теги и команды уже есть), типизированные операции создания, копирования, удаления. Ссылки Entity ID, сохранение, Undo и миграции должны выдерживать эти действия.
2. **Системные взаимодействия:** события касания/входа/использования, селекторы целей, из того же механизма — правила, ловушки, использование еды и базовые способности.
3. **Вещи и волшебство:** переносимые способности/артефакты, инвентарь, улучшение заклинаний, общие ауры и эффекты — не параллельные механики.
4. **Социальная память и развитие:** спутники, фракции, эмоции, перки, наблюдения/эксперименты, непредсказуемые, но закономерные последствия.
5. **Структура приключения:** миры, честные адресные переходы, сценарии, знания сквозь забеги, восстановление после ошибок.
6. **Мета-уровень:** HUD → аватар → чужое авторство Юки → рамка приложения, нестабильность/пустота. Все секреты проектировать от закона к проверяемому маршруту, не от флага и не от чит-кода.
7. **Художественный проход:** локации и интерфейс по docs/18. Изображения и макеты не принимать за уже созданные модели в Godot.

## Инварианты и критерии готовности

- Знание игрока **помогает** повторить секрет уже на первом уровне нового забега; доступ проверяется реальным физическим/системным состоянием, а не отметкой «ранее узнал».
- **Атомарность:** повреждённые данные или неверное правило/заклинание не должны оставлять половину операции применённой; валидация до мутации.
- У любого игрового действия есть **автор и источник** (Луна/Юки/существо/правило/заклинание); это фундамент скрытого расследования.
- Архитектура ограничивает цепочки/спавны/поиски, искажает мир виртуально, не убивает реальные FPS.
- Появление ног, крыльев, рта, смена аватара и роль NPC не должны ломать базовую сущность.
- Новые механики должны пройти отдельные headless тесты и интеграционную проверку главной сцены. Графический результат проверяется отдельно на Mac.
- Новые решения автора фиксировать в docs/06 и обновлять эту матрицу, сохраняя различие **[ПРИНЯТО] / [ПРЕДЛОЖЕНИЕ] / [ОТЛОЖЕНО] / [РЕАЛИЗОВАНО]**.
