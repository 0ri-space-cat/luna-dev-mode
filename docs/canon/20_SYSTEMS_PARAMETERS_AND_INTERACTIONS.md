# 20 — Универсальная игровая система: параметры, способности, реакции, комбинации

> Производственная спецификация V3.1, 09.11.2026. **КАНОН:** простое аркадное взаимодействие с реальными Entity/эффектами, перенос свойств, Bank, понятный русский UI, глубина доступа, безопасный Undo. **ПРОЕКТ:** конкретная номенклатура полей, формулы, цифры, частные реакции и сценарии тестов. Перед реализацией сверить с `docs/02_ENTITY_AND_GAMEPLAY_SYSTEMS.md`, `docs/09_SAVE_AND_EVENTS.md`, `docs/21_ENTITY_TRAITS.md`, `docs/25_COMPONENTS_INTERACTIONS_ABILITIES.md` и текущим GDScript, чтобы не дублировать работающие сервисы.

## 0. Основной цикл игрока
`СМОТРИ → ВЫБЕРИ ОБЪЕКТ → УВИДЬ ЕГО ДЕЙСТВИЕ/СВОЙСТВА → ВЫТАЩИ, ПЕРЕТАЩИ, ИЗМЕНИ → СМОТРИ, КАК МИР РЕАГИРУЕТ → ОТМЕНИ ИЛИ РАЗВИВАЙ ЭКСПЕРИМЕНТ.`
Каждая операция выполняется за несколько действий мышью/контроллером; поля имеют короткую русскую подсказку, иногда ироничный комментарий Луны. В обычной игре код писать не надо. Режим Юки может давать расширенные системные команды для энтузиастов, но все ключевые метазагадки решаются иными наблюдаемыми действиями.

## 1. Объектные уровни и права — НЕ уровни персонажа
| Слой | Примеры | Что делает игрок |
|---|---|---|
| `ENTITY` | слайм, овечка, дерево, холодильник | редактирует базовое существование, поведение, форму |
| `COMPONENT` | двигатель полёта, крылья-спрайт, контейнер, слух | переносит или модифицирует совместимый компонент |
| `EFFECT` | пылает, мокрый, влюблён, невидим, сонный | добавляет/снимает временную или постоянную реакцию |
| `RELATION` | следует за, любит, боится, принадлежит | отдельная направленная связь между сущностями, без неявного стирания личности |
| `SPACE` | дверь, карта комнаты, невидимая лестница, камера | изменяет реальные физические и адресные маршруты |
| `SYSTEM` | поле CHARACTER, ограниченный HUD, оконная граница | глубокие редкие операции при правах и физическом доступе |

`ACCESS_LEVEL` и `SCAN_DEPTH` — свойства инструмента/права доступа, **не XP, LEVEL или дерево навыков персонажа**. Повышение через реальный второй инструмент после озера; выбранные глубокие объекты могут требовать больше прав. При ошибке `ACCESS_DENIED` показать сигнал и обратимую причину без неуязвимого текстового тупика.

## 2. Категории инспектора
**«Общее»** — имя, идентичность, облик, положение, движения и физические свойства. **«Способности»** — переносимые активные и пассивные функции. **«Поведение»** (можно вкладкой после проверки UX) — цель, отношение, маршрут, автоматическая реакция. **«Связи»** — направленные отношения (Лея видит глубже). **«Эффекты»** — текущие статусы и источники. В простом UI не показывать сразу сотни непонятных полей: базовый набор 6–10 карточек и «Показать ещё»/глубина доступа по желанию.

Каждое поле имеет: стабильный технический key, русский label/tooltip, тип/допустимые значения, границу, право чтения и записи, совместимость, обратимость, источник параметра и визуальную реакцию. Данные UI **не должны быть единственным** источником игрового состояния; сущности остаются физическими.

## 3. Базовый набор параметров: прототипные ключи
| Ключ | Тип/пример | Игровой смысл | Комическая/пазловая проверка |
|---|---|---|---|
| `ENTITY_ID` | immutable ID | личность объекта, сохранение/ссылки | смена MODEL не превращает Рина в другой Entity |
| `NAME` | string | видимое имя | переименовать дерево в «Профессор Кустов» |
| `MODEL` | asset ID | спрайт/слои, только форма | холодильник выглядит как овечка, но продолжает охлаждать |
| `SKIN` / `COLOR` | palette | одежда/палитра | розовое дерево с квадратными листьями при наличии ассета |
| `IS_ALIVE` | bool | включённый автономный цикл | оживить лампу, она сама ищет друга |
| `IS_VISIBLE` | bool/режим | визуальное отображение | невидимая баррикада остаётся твёрдой |
| `COLLISION_ENABLED` | bool | физическое препятствие | устранить барьер, не меняя его рисунка |
| `BODY_TYPE` | enum GEL/WOOD/METAL/STONE | физика/реакции | холодный металлический грибок проводит ток |
| `MASS` | положительная величина | импульс/перенос | облегчить валун, поднять его облаком |
| `SIZE` | число/диапазон | масштаб + допустимость дверей | Мия уменьшает ящик для водостока |
| `MOVE_SPEED` | число/границы | скорость перемещения | холодильник догоняет тележку |
| `MOVE_MODE` | WALK/HOP/FLY/SWIM | способ перемещения | слайм прыгает, барашек плавает |
| `GRAVITY_SCALE` | число/вектор | реакция на гравитацию | компас меняет локальный вектор |
| `HEALTH` / `MAX_HEALTH` | неотрицательное | урон, лечение и безопасность | бодрый табурет восстанавливается |
| `HUNGER` / `TIREDNESS` | bounded | упрощённый бытовой цикл | сонный кот ищет тёплый камень |
| `MOOD` | enum/intensity | эмоциональное состояние | мрачный куст перестаёт пугать птичек |
| `FEAR_TARGET` / `LIKES_TARGET` | Entity/group ID | направленные чувства | куст боится грибов, овечка любит лужи |
| `TARGET_GROUP` | group ID | объект взаимодействия/агрессии | забавная «война камней с кустами» |
| `FOLLOW_TARGET` | Entity ID | дружеский эскорт | толпа животных следует за Леей |
| `OWNER` | Entity ID / none | право владения, не воля | изменить владельца ≠ изменить чувства Рина |
| `NAV_ROUTE` | nodes | маршрут патруля/доставки | Юки чинит три пути |
| `DESTINATION_ID` / `TARGET_LOCATION` | address | адрес выхода двери | переправить открытую дверь в скрытый дом |
| `INVENTORY_SLOTS` | bounded | вместимость | котослайм прячет мелкую шкатулку |
| `ACCESS_LEVEL` / `SCAN_DEPTH` | rights/depth | возможности палочки | копия палочки даёт доступ к глубинным узлам |
| `PLAYER_CHARACTER` | valid alias | **системная смена управляющей сущности** | ch_leya, ch_luna, ch_player, ch_oni |
| `CAMERA_FOLLOW` | bool + target | позиция обзора | артефакт фиксирует изображение |
| `WORLD_TIME_SCALE` | bounded | скорость мировой симуляции | песочные часы замедляют общий мир |
| `TIME_OF_DAY` | cycle | фактическое время суток | отражения башни в определённый час |
| `OBSERVER_MODE` | open/closed | взгляд персонажа | застенчивый мост появляется без взгляда |
| `OBSERVED_BY_CAMERA` | computed read-only | находится ли объект в кадре | мост третьего типа твёрд вне кадра |

**Семантика отдельно:** `INVISIBLE` может скрывать спрайт, не отключая коллизию; `INTANGIBLE` может отключать столкновение, не делая вид невидимым; `NOT_OBSERVED` — вычисляемый контекст, а не произвольный переключатель любого NPC. Не добавлять поле с той же функцией под другим именем без миграции/алиаса.

### Правила переноса
Перетаскивание не гарантирует «без последствий»: отсутствие опоры/слота тела вызывает адаптацию анимации или понятную несовместимость. Не требовать заранее отрисовать каждую комбинацию: у некоторых целей растут условные функциональные 2D накладки, визуальные FX, маленькие крылья, магические ножки. Когда нет соответствующего sprite-part, можно показать ауру действия вместо фальшивой формы. `FLY` и «визуально есть крылья» независимы.

Банк хранит идентификатор `ABILITY_ID`, исходного донора, количество переносимых копий, ограничения/тип совместимости. ОТКРЫТО: способность копируется или буквально изымается с потерей у донора — старый мануал предусматривает изъятие; автору важно видеть забавные последствия, но нельзя незаметно навредить питомцу. Доступен `UNDO`.

## 5. Эффекты и стихии — реакции на компоненты, а не списки скриптов
Системы `FIRE`, `ICE`, `ELECTRIC`, `WATER`, `WIND`, `GEL`, `PLANT`, `LIGHT`, `SOUND` должны иметь общие реакции, с учётом `MATERIAL` и содержимого:
- **Огонь + дерево/ткань:** временное горение, искры, нагрев; безопасное тушение водой, восстановление облика без безвозвратной гибели милых NPC.
- **Огонь + лёд:** таяние, лужа/пар. Мия может использовать остаточный статус даже после испарения.
- **Лёд + вода:** ледяная дорожка, изменение скольжения; физически повторяемая головоломка.
- **Электричество + металл/вода:** проводимость через связанную поверхность, ограниченное распространение и видимый радиус.
- **Ветер + маленький/лёгкий:** перемещение, безопасный полёт, отбрасывание предметов.
- **Слайм + вода:** изменение упругости и след скольжения, не одинаково для всех типов геля.
- **Песочные часы + движение:** мир замедляется, сохранённая инерция должна воспроизводимо обновляться; аварийный выход из нулевой скорости всегда доступен.
- **Гравитационный компас + тяжесть:** переносимая зона изменения направления, видимый индикатор нормали.
- **Лея + эмоциональное поле:** некоторые существа сами меняют `FOLLOW`/`AVOID`, если условия жизни изменились. Зрительное отображение связи не доказывает согласия.
- **Тоффи + невидимое существо:** встроенное зрение видит силуэт, Фонарь временно делает видимым другим, закрытые глаза спасают от реакций на взгляд.
- **Камера + мост вне кадра:** коллизия появляется из вычисляемого состояния `OBSERVED_BY_CAMERA`, не из прохождения квеста.
- **Застенчивый мост + закрытый взгляд:** после наглядной задержки появляется опорная поверхность; счётчик сбрасывается понятно, с аудиосигналом и безопасным падением.
- **Проекционное поле палочки + оставленный инструмент:** за границей проекции обнаруживаются скрытые структуры без обязательной Юки.

## 6. Условная магия без программирования
Вся магия `WHEN→IF→DO` реализуется с **визуальными карточками**: КОГДА [кто-то подходит] / ЕСЛИ [это куст] / ДЕЙСТВИЕ [сделать розовым]. Игрок переносит готовые плитки, может выбрать пресет и увидеть понятный предпросмотр. Консоль Юки может показывать более сложную форму, но обычная игра никогда не требует написания синтаксиса. Максимум разрешённой нагрузки — 2–3 простых связанных правила на объект в раннем прототипе; ограничить циклы и рекурсию для FPS.

## 7. Пять системных сценариев, которые обязаны работать
### A. «Война кустов и камней»
Поменять `IS_ALIVE` у камня, добавить `WALK` с другого существа и `TARGET_GROUP=BUSHES`, скорость безопасно ограничена. Камень сам идёт к ближайшему кусту. Лея видит, что куст боится камня; другой игрок меняет чувства либо переводит группу на дружбу. Изменения должны оставаться после перезахода в сцену.

### B. «Холодильник с крыльями»
Оживить холодильник, назначить `FLY` облака и `COOL` у него оставить. Для тяжёлого тела нужен уменьшенный `MASS` или видимый магический компенсатор. Иначе он взлетает медленно, не ломая симуляцию. Подобранные предметы не исчезают.

### C. «Застенчивая дорожка»
Не видно моста; птица и яблоко ведут к первой системе. За ним другой мост появляется только при закрытых глазах; игра показывает по звуку прогресс материализации. Двигаться, не видя мост, можно по ориентирам, с быстрым возвратом.

### D. «Утка и часы»
Утка не успевает доставить письмо. Игрок меняет скорость физического механизма башни (не обязательно глобальный `WORLD_TIME_SCALE`), перенаправляет путь, или передаёт `FLY`; квест завершается по фактической доставке, а не по одному скрипту.

### E. «Овца ненавидит траву»
Если игрок меняет `TARGET_GROUP`/`HATES_GRASS`, овечка начинает преследовать травяные сущности. Но новые факты не должны приводить к жестокому физическому насилию; можно играть в гонки, ругаться, разбрасывать пыльцу, а не обязательно уничтожать NPC.

## 8. AI, отношения и причинность
Лёгкий `BehaviorPlanner` с небольшими состояниями и целями, не невидимый «всемогущий AI». События от изменения объекта публикуются в журнал: `actor_id`, `target_id`, `field`, `old/new`, `world_tick`, `source`; подписи Юки и древние архивные изменения способны существовать до детективных сцен. При ручном вводе `CHARACTER` сменяется **управляемый субъект**, не переписывается `Entity ID` и память окружающих.

Лея взаимодействует с `EmotionState` и `RelationshipEdge(from,to,type,intensity,consent)`. Привязанность может быть односторонней, а страх — естественной реакцией на события. Нельзя делать магическое перетаскивание любви автоматическим доказательством согласия. Важные сюжетные связи имеют особые ограничения, но они должны быть объяснимы, не просто `LOCKED` без физической причины.

## 9. Ограничения производительности и отката
Потенциальные комбинаторные взрывы: размножение слаймов, массовое оживление предметов, бесконечные триггеры `WHEN`, копирование палочек, физическая вода, десятки анимированных мелких существ. Решение: лимит на активные компоненты в области, число копий, очередь реакции за тик, объединение далёких эффектов, ограниченные сетки потоков, редкая симуляция вне камеры. Но ограничения должны объясняться одной устойчивой механикой, не появляться внезапно только на сильных метасекретах.

`SaveService` хранит идентичность Entity, изменения в мире, инвентарь, нестандартные решения, забытые/восстановленные места и источник прогресса. `Undo/Redo` возвращает не только цвет, но и настоящие связи/наличие компонентов, без циклов ссылок. Самоудаление Луны, превращение в неподвижный объект, телепорт без возврата, стоп времени — всегда безопасны.

## 10. Что должно попасть в первые автоматические проверки
- Передали `WALK` на холодильник — тот двигается и сохраняется после перезагрузки.
- Разный `MODEL` на том же ID не перезаписывает историю и отношения.
- Озеро создаёт действительно отдельный инструмент (новый Entity ID), и один редактирует другой, не самого себя.
- `CHARACTER` нормализует алиасы и не создаёт Они из воздуха.
- Дверь по действительному адресу работает независимо от того, как игрок получил адрес.
- Постоянный невидимый мост не меняет коллизию при смене персонажа/изображения.
- Другие виды наблюдения различаются; `OBSERVED_BY_CAMERA` не приравнивается к `EYES_CLOSED`.
- Пустота и ранний вход не повреждают сохранение.
- Эффекты жидкости/источника работают после скрытия визуального декаля.
- Глубокая рамка не взаимодействует с реальными файлами ОС и не вызывает реальный краш.
