# 10 — Экономный 2D-артпайплайн и живой мир

> **КАНОН ДИЗАЙНА / 08.11.2026.** Основной режим игры — **2D в Godot**, без обязательной 3D-геометрии и без переключения 3D↔2D. Дизайн следует утверждённой яркой, мягкой, детализированной рисованной сцене с неоновым интерфейсом. Цель — минимум дорогих отдельных генераций и максимум переиспользуемой живой анимации. План кода — [11](11_2D_IMPLEMENTATION_PLAN.md), переносимые свойства и спрайт-якоря — [09](09_PROPERTY_TRANSFER_SYSTEM.md).

## 0. Что считаем «генерацией»

**Генерация** = один запрос к внешнему генератору, а не один файл. В одном запросе можно получить 3–8 согласованных кадров/спрайтов на одном sheet, **но** рассчитывать на идеальный match поз и прозрачности нельзя. Сначала генерируем **мало ключевых исходников**, затем вручную/скриптом приводим к сетке и **кодом** создаём вариации. Один длинный GIF или 24-секундная видеогенерация для каждого объекта — слишком дорого и нестабильно.

**Бюджет первой играбельной сцены**: ориентир **12–20 внешних генераций** на ландшафт, главную героиню и два существа (плюс ручное разделение/подчистка); нижняя граница возможна только при использовании уже имеющихся референсов и простых silhouettes. Для полноценного набора одного биома после вертикального среза — ещё 10–18 генераций; это планирование, **не гарантированный** счёт. Отдаём приоритет повторяемости, а не абсолютному числу картинок. При плохом результате не генерировать всё заново: исправить отдельные детали вручную и использовать rig/deformation.

**Единый эталон (style contract):** сказочный высококонтрастный 2D-cartoon, чистый тёмно-фиолетовый контур, насыщенные зелёные поля, сиреневые скалы, бирюзовая вода, розовые цветы/кристаллы, легко читаемые силуэты, мягкие тени, небольшие неоновые акценты. Избегать пластиковой 3D-модельности и «почти 3D» макетов с неконтролируемыми ракурсами. Одна логическая камера для карт в духе авторского концепта: фронтально-сверху на платформы и уступы, персонажи читаются целиком, глубина имитируется перекрытием/параллаксом/сортировкой по Y. Это 2D-изображение и 2D-коллизии.

## 1. Общие технические стандарты

| Назначение | Рабочее правило |
|---|---|
| Сцена / базовый viewport | Макет 1280×720; рендер адаптируется к 16:9 и другим отношениям, не вырезая UI |
| Модуль окружения | Базовая логическая клетка 64×64 px; при zoom целочисленное масштабирование только для пиксельного UI, фоновый рисованный мир может интерполироваться |
| Мир | `TileMapLayer`/аналог 2D, CanvasItem shader, `AnimatedSprite2D`, `Sprite2D`, `AnimationPlayer`, `Bone2D`/`Skeleton2D`, `GPUParticles2D`, `Light2D`, `Area2D` |
| Цвет и исходники | PNG RGBA без фона для героев/пропсов; карты — атласы; хранить исходный sheet, маски, pivot и финальные экспортные кадры |
| Контур | Видимый при размере 1×; не полагаться на тонкие невидимые линии генератора |
| Границы | У каждого кадра одинаковый canvas, один pivot, стабильный масштаб, одинаковая ориентация/освещение; не допускать «прыжка» персонажа между кадрами |
| Кадровая частота | Для лёгких циклов обычно 4–8 фаз при 4–10 FPS; не требовать 24 уникальных кадров на событие |
| FX | Один универсальный атлас/шейдер/particles + якоря, а не новый эффект на каждый тип цели |
| 2D-изнанка | Одна светло-голубая/`#8FECFF` неоновая контурная палитра для мира; не генерировать 7 разных тайлсетов |
| Принадлежность цветов | Темы HUD/редактора зависят от **управляемого героя**, мир/изнанка от этого не перекрашиваются |
| Физика | Художественные свесы/навесы в визуальном слое; реальные `CollisionShape2D`/navigation/occlusion привязаны к геометрии, не к фантазии рисунка |

**Файловая дисциплина**: `assets/2d/<biome>/<group>/<object>/` с `source.png`, `parts.png` или `sheet.png`, `atlas.png`, `material.json`, `anchors.json`, `animation.json` (имена согласуются с импортом в Godot). Исходные промпты и плохие варианты — в `art/source/2d/`, годные игровые PNG — в `assets/2d/`. Например: `assets/2d/eternia/environment/waterfall/flow_sheet.png`, `assets/2d/characters/luna/rig/hair_back.png`, `assets/2d/properties/fly/wings_sheet.png`. Эти **пути плановые**, пока не означают созданные файлы.

## 2. Алгоритм одной генерации и критерий приёмки

1. Выбрать **один** артефакт производства: «овечка, исходник для нарезки частей», а не «вся Этерния со всеми существами».
2. Подготовить **эталон цвета и масштаба**, силуэт/референс, базовый ракурс, функцию предмета. Указать, что нужно получить: отдельные варианты, лист из N кадров, строгие одинаковые размеры ячеек, без подписей внутри арта.
3. Принять или отклонить **силуэт** и основные цвета **до** массовой итерации. Для кадров использовать опорную утверждённую модель, не независимые генерации со случайным дизайном.
4. Удалить фон, привести контуры и pivot; для тайлов вручную состыковать края, для персонажа разрезать на части; подготовить маски, alpha-test.
5. Сделать один **технический proof** внутри Godot: idle/walk/свет/тени/коллизия, а не только красивый contact sheet.
6. Добавить семантику: atlas coords, collider, animation frames/FPS, anchors, effect sockets, visual recipe. До принятия не генерировать 30 связанных вариаций.
7. Проверить PNG при 1×, 2× и на типичных фонах; сравнить в тёплой дневной сцене, ночной сцене и светло-голубой изнанке.
8. Фиксировать статус: `planned / source_generated / cutout_done / rigged / animated / integrated / verified`. «В репозитории» и «игра работает» — разные статусы.

## 3. План генераций по очереди

### P0 — эталон и тестовый рендер (0–2 генерации)

**Вход:** утверждённый концепт с Луной, водопадом, бегущими предметами, правой панелью взлома и HUD. Использовать его как стилевой reference, не растягивать всю картинку в фон игры.

**Выход:** цветовая палитра, толщины обводок, 64px-масштаб тайлов, пропорции Луны и овечки, 3 тестовых скриншота (обычный день/изнанка/ночь), fixed UI safe zones. Содержимое WorldTruth и интерфейса остаётся разделённым на независимые слои.

**Генерировать:** при необходимости только отдельный style sheet со всеми одобренными референсами; не пытаться получить финальную карту одним изображением.

### P1 — геометрия Этернии: один маленький кусок уровня (2–3 генерации)

**Сначала сгенерировать / нарезать:**
- `ground_base`: 3 варианта травяной поверхности без приметных объектов и повторяющихся звёздочек;
- `ground_transitions`: прямые края N/E/S/W, внешние/внутренние углы, мягкий переход к тропе/скале;
- `cliff_side`: 2 варианта стены уступа, торец, верхняя кромка, нижний край, один маленький блок «ступень»;
- `path`: 2–3 дорожных плитки, поворот и стык;
- `bridge`: одна простая конструкция, коллизия отдельно, видимость независимо от существования.

**Не генерировать:** все 47 комбинаций соседних плиток. Автотайлинг/terrain sets, flips и окраску по seeded variation делает движок. Каждый модуль обязан соединяться со своими копиями по клеточной сетке. **Acceptance:** из одного набора собрать две визуально непохожие поляны с коллизией и проходами, без видимых швов на 10×10 клетках.

### P2 — крупные пропсы и смена времён/слоёв (1–2 генерации)

**Выход:** 2 формы деревьев (ствол + крона отделены), один куст, цветы (3 компактных кластера), 2 кристалла, арка/руина, камень, ящик и мост. Глубина через перекрытие и `y_sort_enabled`; для больших деревьев ствол коллизионный, крона визуальная. Для деревьев с разумом — **отдельный лицевой оверлей**, а не новая версия всего дерева.

**Варианты:** дневной спрайт один; ночь и изнанка — shader/Light2D/контур. Не создавать тройной набор PNG для каждого времени суток и каждого героя. **Acceptance:** Луна проходит за деревом, не проходит через ствол, а кристалл мерцает независимо от сцены.

### P3 — вода и водопад (1–2 генерации)

**Разбить на:** `waterfall_top` (верхняя губа 1), `waterfall_mid` (универсальный повторяемый средний сегмент 4–6 кадров), `waterfall_bottom` (пенистый удар 4 кадра), `waterfall_foam` (4 кадра), `water_surface` (4 кадра, тайлится), одна маска mist. Важнейшее требование — кадр N без рывка переходит в кадр 1, края водопада и середина совпадают. Для водопада высотой 1, 3 и 8 тайлов используем один центральный цикл, меняем только его число повторов.

**Кодом:** `AnimatedSprite2D` / UV-scroll шейдер для струй, `GPUParticles2D` для брызг, `Light2D` или shader для небольших бликов, анимированная маска брызг. Частицы не должны заполнять всю сцену и заслонять интерактивность. **Acceptance:** один набор работает как минимум у двух водопадов разной высоты, без повторной генерации кадров.

### P4 — микрожизнь и фон (0–1 генерация)

**Исходники:** 1–2 силуэта бабочек (крылья можно анимировать зеркальным отражением); 1 светлячок-точка; 1 искра пыльцы; 1 лепесток; один небольшой лист. Опционально 2–3 кадра бабочки.

**Кодом:** `AmbientSpawner2D` с детерминированным seed, мягким случайным дрейфом, редкими паузами на растениях, разбросом фаз, лимитом популяции, временем суток и событиями взлома. Не лепить светлячка на каждый тайл: кластерный спавн только в отмеченных ambient-зонах с локальными плотностями. Статичный фон оживает за счёт редких событий, а не глобального 100% непрерывного движения. **Acceptance:** за 20–30 секунд сцена несколько раз незаметно меняется, но при остановке кадра не выглядит шумной.

### P5 — Луна: один рисунок, разрезанный на части (2–3 генерации)

**Не делать десятки отдельных полных кадров одной героини.** Сделать один строгий `character turnaround` (основной ракурс + опциональный профиль) и один `parts sheet` в том же масштабе: `hair_back`, `body`, `head`, `hair_front`, `hat`, `glasses`, `eyes_open/half/closed`, `mouth_neutral/smile/surprised`, `upper_arm_L/R`, `forearm_L/R`, `hand_L/R`, `legs_L/R`, `feet_L/R`, `wand`, `backpack`.

**Внутри Godot:** `Skeleton2D/Bone2D` или `AnimationPlayer` для idle/breath/walk/cast/turn, покачивание волос и шляпы через небольшое вторичное движение, отдельная анимация лица, шага и магии. Глазки и рот — сменные sprites, не перерисованный весь персонаж. Первые циклы: idle 4 позы/ключа, walk 4–6 фаз или кости, cast 3–4 фазы, interact 2, hurt 2. Если камера требует двух ракурсов, **сначала** основной и зеркально отражённый, а затем дополнить боковой/задний там, где игра реально их показывает. **Acceptance:** 30 секунд живой idle без видео и перемещение со сменой позы, поворотов, тени и коллизии.

### P6 — овечка, холодильник, одно ожившее дерево (2–3 генерации)

**Овечка:** `body`, `head`, `legs_L/R` (либо набор из 4), глаза/рот, `idle` и `walk`. Минимум idle 2–4 фазы, walk 4–6, react 2.  
**Холодильник:** корпус, дверь, отдельный экран/глазки (если нужны по дизайну), пятно тени, `static` + `alive_wobble`, `move` через общий squash/stretch шаблон. **Не генерировать овечьи ноги для холодильника**.  
**Дерево:** ствол/крона/ветки, отдельная мультяшная мордашка прямо на коре, `talk` 2 фазы, `wobble` 2 фазы, корни как необязательная locomotion-накладка.

Для разных оттенков/размеров использовать параметры материала и трансформации, а не новый лист. **Acceptance:** у всех объектов реально работают живые состояния и разные функции поведения, не только `Sprite2D.position`.

### P7 — библиотека переносимых способностей (1–3 генерации)

**Первый пакет свойств:** `WALK`, `FLY`, `FIRE_BREATH`, `GLOW` + иконки интерфейса. Генерация общего **FX-sheet**:
- крылья **раздельно** (левая/правая), 3–4 фазы взмаха + одна сложенная поза, общий контур, прозрачность;
- пламя: 4 кадра с единым основанием у `front_output`, один всплеск;
- электрические разряды: 2–3 варианта линий, для следующей партии;
- сияние и тень: шейдер/градиент, не несколько генераций;
- WALK/плавание/корни: code motion template + опорные части, а не отдельный лист всех существ;
- аура/состояния: процедурные контуры и палитры + универсальные эмоты.

**Важнее самого арта — anchors и рецепты**: для каждого существующего объекта `body_center`, `back_left/right`, `front_output`, `feet_base`, `ground_shadow` и т. п. `FLY` должен работать хотя бы на овечке, холодильнике, дереве и бочке; подстройка якорей делается **в метаданных конкретного объекта**, без новой генерации крыльев. Разрешены смешные пересечения слишком многих эффектов; UI/коллизии/выход из состояния не ломаются.

### P8 — 2D-изнанка и уникальные виды зрения (0–1 генерация)

**Базовая изнанка** общая: обычные спрайты приглушаются, контуры объектов и доступных целей светятся светло-голубым (`#8FECFF`), появляются линии скрытых структур/связей, пунктир условно невидимых объектов. Вся физика продолжает существовать в WorldTruth независимо от переключателя восприятия.

**Кодом:** `CanvasItem` shader/outlined secondary pass, `CanvasModulate`, `Light2D`, прозрачные маски и отдельный визуальный слой. **Не делать семь разных версий каждого тайла по цветам героев.** У Юки уникально проявляются невидимые маршруты/мосты, у Леи связи/потребности животных, у Тоффи — скрытые носители островов; дополнительные сущности и ауры — через `PerceptionLayer2D`, не перекраску всей земли. Эмоциональные ауры Луны через Кристальное сердце = shader/particles, глубокие причинные связи Леи = линийный procedural renderer. **Acceptance:** секретный мост имеет одну коллизию и один Entity ID в обычном мире и изнанке, хотя во второй можно его увидеть.

### P9 — UI и инвентарь (0–1 генерация, по необходимости)

Сначала попробовать использовать **уже загруженные** `assets/ui/common/`, `assets/ui/hack/`, `assets/ui/themes/<character>/`, `assets/characters/<id>/ui/`, `assets/artifacts/<ID>/`. Уже есть панели, вкладки, 7 цветовых тем, иконки, портреты, рюкзаки, 21 мастер артефакта (его concept/icon — копии одного исходника, не 42 уникальных кадра).

**Новая работа чаще кодом:** вместо baked-текста наложить русские `Label` и технические `KEY` отдельно; смена темы редактора через `active_character_theme`, NinePatch/TextureRect вместо CSS-like заглушек; окно должно следовать **новому горизонтальному прототипу с правой панелью**, если именно он утверждён снимком 08.11.2026, а не прежнему узкому mockup из docs/art. Кнопка **«Сохранить»** на русском, вкладки **«Общее»**, **«Способности»** и прочие — на русском; свойства внутри — `WALK`, `FIRE_BREATH` и русские tooltip. Банк — интерфейс данных, а не отдельный 2D-артдроп.

**Критерии:** читабельность на 1280×720, 1920×1080, мобильном/неполноэкранном оконном разрешении (скролл вместо переполнения), переключение семи цветовых тем без перезапуска, семантические цвета ошибок сохраняются, текст не baked в SVG. **Призма** показывает существующую голубую изнанку hands-free, без новой палитры/системы тайлов. **Глаз Оракула** — отдельный ещё не сгенерированный 2D-окуляр на лице Луны: 1 мастер и небольшое движение шестерёнки, 0 новых карт.

## 4. Единая схема производства разных вариантов

| Группа | Генерируем минимально | Дальнейшие варианты | Автоматизация |
|---|---|---|---|
| Трава | 3 бесшовных варианта + края | Шевеление, пыльца, бабочки | Seeded autotile, shader, spawner |
| Водопад | верх 1 + середина 4–6 + низ 4 + пена 4 | Любая высота/ширина кратно модулю | Повторяемая UV/sprites, particles |
| Дерево | 2 кроны + 1 ствол/вариант | Размеры, шевеление, лицо, крылья | Bones, masks, procedural anchors |
| Главный герой | 1 clean character reference + 1 sheet слоёв | Idle/walk/hack/эмоции | Rig, animation track, blend |
| Зверушка | 1 layered source / вид | 4 шага, 2 эмоции, чужие способности | Rig presets + shared FX |
| Предмет-существо | 1 нейтральный проп + дверца/лицо | WALK/FLY/FIRE_BREATH | Squash/stretch + anchors |
| Крылья | 1 пара раздельно, 3–4 кадра | На бочке/дереве/рыбе/человеке | Attach/pivot/scale + z layer |
| Эмоции | 0–1 generic aura texture | Сила, цвет, направленные связи | Shader, noise, spline paths |
| Неон изнанки | 0 | Силуэты/свет/скрытые слои | 2D shader, CanvasModulate |
| UI | Существующие SVG/PNG | Семь тем, перевод текста | Theme + localization + NinePatch |

## 5. Что делать не генерацией, а программой

**Не тратить запросы** на изменение палитры семи персонажей, сезонные/ночные тайлы, масштаб деревьев, микроблики/пыль, свечение аур, редких светлячков, шевеление листвы, колебание воды, тень при полёте, глитч при взломе, подсветку кликабельного, индикатор отношения, смену значений UI и иконки простых параметров. При необходимости сделать один собственноручный SVG как основу.

**Кодовые сущности**: `AmbientSpawner2D`, `TileVariantResolver`, `EntityVisualController2D`, `EntityRig2D`, `PropertyOverlayResolver`, `PerceptionLayer2D`, `VisualLODManager`, `WaterfallComposer2D`, `CharacterThemeController`. Это имена **планируемых** компонентов, а не утверждение о существующих классах.

**Живость сцены измеряем:** в состоянии без действий игрока видно не меньше 5 различных ненавязчивых событий за минуту (вода, ветер, движение NPC, микроорганизмы, смена света, мимика), и не меньше трёх из них возникают из системных правил/рандомизации, а не из baked GIF. При скрытии всех ambient-частиц игра по-прежнему читаема и работает без потери симуляции.

## 6. Правила экономии и производительности

- Вьюпорт управляет LOD: не тикать AI/частицы вне кадра без причины; WorldTruth и сейв NPC остаются корректными.
- Использовать `MultiMeshInstance2D` или пуллинг простых микрочастиц только после профилирования; не заводить отдельный `Timer` на каждую травинку.
- Подружить анимации по фазе с лёгкой рандомизацией начала; избегать 100 водопадов, которые все синхронно дёргаются.
- Для UI/FX различать плотную пиксельную графику и рисованные исходники: один `texture_filter` на всё может испортить половину ассетов.
- Не генерировать все семь героев как полностью анимированных до проверки одного рига Луны и первой овечки.
- Каждый новый тип `Property` сначала получает корректный логический обработчик и **fallback**, затем уникальный визуал, только если он реально улучшает игру.
- Генерации исключительно по небольшим утверждённым партиям; хранить метаданные, не «всё с нуля» после каждой правки.

## 7. Условия завершения минимального вертикального среза

- Два разных участка одной поляны из одних тайлов, вода и составной водопад, 1 скрытый мост в физически едином мире.
- Луна ходит/играет idle/взламывает и реагирует, один NPC овечка, один холодильник, одно ожившее дерево.
- Овечка теряет `WALK`, холодильник получает `WALK`; затем бочка/холодильник получает `FLY`, крылья прикреплены к правильным anchors, тень реагирует; `FIRE_BREATH` испускается из осмысленной точки.
- `AmbientSpawner2D` показывает светлячков/бабочек, вода движется, листья реагируют на ветер; несколько живых систем работают автономно.
- Отрисовка и коллизии после переключения изнанки соответствуют **одному WorldTruth**, без перегенерации уровня и семи цветовых тайлсетов.
- Русские интерфейсы, технические имена только в панели данных, осмысленные подсказки; активный персонаж меняет акцент UI и окна взлома.
- Один слот сейва выдерживает взятие/передачу способностей, **надетый Глаз Оракула** при обычной загрузке и память о пройденном туториале при новом цикле; повторный цикл требует реального быстрого взлома палочки и получения глаза, но не катсцен/обязательных разговоров.
- Тесты проходят на одной Godot-версии из CI; на слабой машине проверить, что анимации и particles не блокируют управление.

**Главное правило:** хорошее живое 2D достигается одинаковыми законами анимации и переиспользованием небольшого числа исходников. Количество GIF и уникальных кадров не является метрикой качества.
