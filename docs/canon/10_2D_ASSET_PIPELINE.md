# 10 — Арт-пайплайн LUNA: модульный пиксель-арт

> **Решение автора от 08.11.2026:** актуальная спецификация — [18 — модульный пиксельный мир](18_MODULAR_PIXEL_ART_CANON.md). Эта глава описывает практический выпуск ассетов и заменяет прежнюю схему рисованных 2D-ригов и множества независимо сгенерированных травяных тайлов. Реальные результаты сверять с Godot, не с концепт-артом.

## 1. Разделение обязанностей

**ImageGen:** художественная форма, палитра, текстура, освещение, силуэт; отдельные прозрачные PNG-кандидаты. Сначала мастер, затем согласованные варианты на его основе.

**Godot:** базовая сетка и ландшафт, размещение готовых прозрачных спрайтов, автотайлинг рельефа, Y-sort, коллизия, навигация, освещение, спрайт-листы, shader/particles/фоновые события.

**Скрипты технической подготовки:** проверка настоящего RGBA, границ, размера и визуального масштаба, сборка атласов из одобренных исходников, цветовая нормализация по утверждённой палитре, стабильный seed. **Не создавать художественные ассеты программным рисованием** из фигур или шумов.

## 2. Единый стиль

- Пиксель-арт с читаемыми квадратными пикселями, сочной, но мягкой зеленью, сиреневыми скалами, бирюзовой водой, розовыми и фиолетовыми магическими акцентами; аккуратные тёмно-фиолетовые контуры на объектах, без тотальной неоновой обводки окружения.
- Игровой мир под углом сверху 3/4, поверхность грунта — сверху. Никаких side-scroller/hack-and-slash/3D-рендеров для новых ассетов.
- Базовый мир 64×64 world units; исходный нейтральный тайл 32×32 и отображение в ×2 через Nearest. Отдельные детали могут быть больше клетки. Изображения ImageGen принимаются в рабочем масштабе только после визуального контроля при реальном уменьшенном размере.
- Одна карта утверждённой палитры и освещения для всего биома. При новой генерации давать предыдущий мастер в качестве визуального референса. Малые расхождения допускается корректировать технически; явный стилистический разнобой отклонять.

## 3. Сборка растительности

1. Один спокойный травяной `ground_base` без ярких отличительных элементов — повторяемый фундамент. Не генерировать 12 отдельно окрашенных оснований.
2. Маленькие PNG на прозрачном фоне: `grass_tuft_small_01...`, `clover_01...`, `daisy_cluster_01...`, `pink_flower_01...`, `bush_01...`, `mushroom_01...`, `crystal_01...`; каждый отдельный, независимо размещаемый объект.
3. `DecorSpawner2D` (планируемый, ещё не реализован) считывает список разрешённых элементов для биома, вес появления, группировку, площадь, exclusion masks, seed и ограничения на пересечения. Размещает их поверх основы; для ключевых сцен используется ручная корректировка.
4. Разные сочетания получаются от позиций и плотности декора, **без повторной генерации текстуры земли**. Не смешивать светлые/тёмные основания случайно, создавая клетчатую карту.
5. Приёмка: небольшой и большой участок, проверка на повторяющийся узор и пустые пространства для движения, сопоставимость с персонажем и крупными пропсами.

## 4. Составные скалы, дороги и вода

**Скалы:** отдельные авторские кусочки `cliff_face`, `cliff_lip`, `cliff_corner_inner/outer`, `cliff_end`, `cliff_base`, `steps`. Правило выбора по соседям делает Terrain Set/автотайлер. Высота обрыва — повторение допустимого среднего сегмента, оформление — прозрачными лианами, мхом, цветами, трещинами, кристаллами; физика и Y-sort отдельно. Проверка на двух разных по форме и высоте уступах.

**Тропа:** тайлы прямых участков, повороты, углы, ответвления, переход на траву. Декор спавнится с исключением проходов. Одна нарисованная тропа на весь уровень не подходит.

**Вода:** несколько согласованных кадров поверхности, повторяемая средняя часть водопада + верх и низ; динамика через `AnimatedSprite2D`, UV-сдвиг и умеренные частицы. Настоящие изображения воды нужно создать художественно, а не прямоугольниками GDScript.

## 5. Персонажи и магические способности

- Статичный первый мастер Луны с утверждённым силуэтом → согласованные 4 направления → короткие циклы `idle/walk` → `run/cast/react`. Единый baseline и pivot; не принимать кадры с разным количеством ног, неверными очками или разъехавшейся шляпой. Ориентир исходного кадра ~48×64 (не абсолютное ограничение).
- Овечка, холодильник и ходячее дерево получают **собственные покадровые циклы движения**, соответствующие анатомии. Старый процедурный риг с отдельно приделанными ногами является временным экспериментом, не планом финального арта.
- При переносе `WALK/FLY/FIRE_BREATH/GLOW` функция Entity не зависит от рисунка. Накладки для крыльев/аур/частиц можно процедурно крепить по `anchors`; это не замена полноценной ходьбы.

## 6. Статус и критерии приёмки

`idea → ImageGen_source → visual_approved → cutout_or_atlas_validated → integrated_in_Godot → in_game_QA_passed`.

- Проверить PNG/RGBA без ложного «шахматного» или зелёного фона; размеры на реальной сетке и без размытия; palette consistency.
- Для базовых тайлов: бесшовность и 10×10 повторений. Для скал и троп: валидные комбинации соединений, в т. ч. углы. Для декора: размещение с фиксированным seed, отсутствие перекрытий/перегруза.
- Нужны реальные снимки из Godot и зелёные проверки CI; красивый лист ImageGen без раздельных игровых исходников считается только концептом.
- Платные сторонние генераторы не требуются в стартовом пайплайне. До возобновления работ см. актуальную [очередь](13_GENERATION_BATCHES.md) и [runtime-статус](14_2D_RUNTIME_MIGRATION_LOG.md).
