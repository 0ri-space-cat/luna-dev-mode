## Что считать ценным
1. `scripts/` — Entity, события, эффекты, правила, инвентарь, сохранения, Undo/Redo, существующий прототип взаимодействий. Нельзя удалять до регрессионного теста и оценки переносимости в 2D.
2. `scenes/main.tscn` — старый 3D/graybox. Пока оставляем и помечаем как legacy runtime; не заменять новой сценой одним неудачным тестом.
3. `scenes/2d/world_2d.tscn` на feature-ветке — тестовый 2D runtime и потенциальный будущий фундамент. Не объявлять утверждённым финальным видом без художественной приёмки.
4. `assets/` и `art/` — тысячи старых SVG и ассеты 21 артефакта, UI и персонажей; вероятно много невостребованного или повторяющегося, **но без проверки импортных ссылок и лицензий удалять опасно**.
5. `docs/archive/` — архив старых подробных сценариев 00 и 28–42, остаётся главным хранилищем сцен и альтернативных подходов.
6. `docs/canon/` до 09.11 — прежняя единая библия, снимок сохраняется в `docs/archive/2026-11-09-pre-eternia/`.

## Будущая техническая чистка — отдельный PR после аудита
**Этап A — факты:** запустить оба прототипа в Godot, документировать entrypoint, Godot-версии, скриншоты, какие systems реально живые, какие ассеты импортируются. Снять тестовые baseline. Проверить ресурсы `res://`, ссылки внутри сцен и доступность скриптов.

**Этап B — зависимость ассетов:** собрать отчёт по реально используемым файлам/дубликатам по хешам, пустым тестовым каталогам, старым 3D-артефактам; оценить, что можно хранить только в исторической ветке или архиве.

**Этап C — решение автора:** после подтверждения эстетики определить новый runtime по умолчанию. Возможно сохранить graybox в `legacy/` и убрать его из основных точек запуска, но только после теста непрерывности функций/Save.

**Этап D — безопасная чистка:** переместить устаревшие материалы с `git mv` либо оставить Git-архивную ветку и дать явную таблицу удалений; не чистить объекты, на которые есть ссылки, и не мерджить удаление невидимых из документации ассетов.

## Инженерные требования к новому 2D
- Точный авторский вид Луны и 1–2 существ в реальном игровом масштабе; большой пиксель-арт без «16px игрушек» и некачественных коллажных спрайтшитов.
- Одна повторяемая спокойная трава, отдельные мелкие детали, непрерывное движение, камера и коллизии.
- Сначала сцену визуально утвердить, затем налаживать универсальное изменение `Entity`/компонентов, перенос модулей, флаги зрения/контроля камеры.
- Секретные уроки и механики проверять физикой в одном slice, прежде чем производить несколько биомов.
- Никаких 3D сцен ради `ch_<имя игрока>` или виртуального рабочего стола — рисованный 2D монтаж.

## Объективные тесты для следующего PR
- Точка запуска проекта действительно существует и открывается в Godot.
- Не пропадают уже работающие команды, события и сохранение при переходе 2D.
- Артефакты и имена в JSON-манифесте не внезапно пересоздают предметы.
- Скрытые коллизии существуют до выбора профильного героя.
- Ввод неизвестного CHARACTER и недействительного адреса не разрушает сейв.
- Новые места и уровни не требуют неточной симуляции доступа к файловой системе игрока.
