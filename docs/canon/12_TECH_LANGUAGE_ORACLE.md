# 12 — Технический язык мира, Оракул и сохранение понимания

> **КАНОН / 08.11.2026.** Сюжетная система знакомства с внутренним кодом реальности, **без дерева навыков, XP и «покупки расшифровки»**. Работа Оракула — дать Луне **понимание текста**, а не разрешить использовать ранее неработающие операции. Совместить с [передачей способностей](09_PROPERTY_TRANSFER_SYSTEM.md) и [редактором](04_HACKING_MANUAL.md).

## 1. Правило языка UI

**Вся игра на русском:** диалоги, титры, меню, инвентарь, карты, названия вкладок, действий, предметов, всплывающие подсказки, описания способностей, кнопка **«Сохранить»**, имя объекта «Клён», «Овечка», «Холодильник», «Банк способностей», «Извлечь», «Передать».

**Технический слой — единственный намеренный англоязычный язык:** идентификаторы данных `HEALTH`, `IS_ALIVE`, `MOVE_SPEED`, `AI_ENABLED`, `BEHAVIOR_MODE`, `WALK`, `FIRE_BREATH`, `SCAN_DEPTH`, служебные `ID`, `TRUE`/`FALSE`, машинные ключи формул. Это «волшебный язык» самой симуляции; его русские tooltip раскрывают смысл, но **называют ключи без перевода**, чтобы игрок мог обнаруживать и запоминать их как заклинания.

**Новые главные вкладки:** «Общее» (скаляры и логические поля), «Способности» (доступные модульные свойства); отдельная панель **«Банк способностей»**. Если нужны прежние вкладки «Облик», «Физика», «Разум», «Поведение», «Отношения», «Реакции», «Ауры», «Теги» — оставить их на русском; не размещать десять подписей в одну нечитаемую строку, использовать иконки и русские подсказки с доступным hover/focus/touch. Строки визуально примерно такие: `HEALTH   120/120` (подсказка: «Запас здоровья: сколько урона выдержит существо»); `FIRE_BREATH` (подсказка: «Может выпускать огонь из передней точки тела»).

**Важно:** текст параметра — слой UI поверх игрового текстового/машинного идентификатора; шифр и перевод **не меняют сохранённый ID**, логику CommandProcessor, Entity или имена ресурсов. Никаких `ЗДОРОВЬЕ` вместо `HEALTH` в игровых данных.

## 2. Пролог: разлом, чужие знаки, первое случайное изменение

1. В Этернии Луна находит **пространственно-временной разлом** у ручья. Она действует своей обычной волшебной палочкой; разлом касается её, палочка начинает видеть «внутренние» поля мира. У инструмента появляется реальная возможность редактирования Entity и простых NPC-маршрутов, а не только новый визуальный эффект.
2. Впервые на дереве/предмете открывается знакомое игроку окно взлома, **все обычные элементы UI на русском**, но имена **технических** полей выглядят как непонятные псевдорунные знаки. Например, вместо `IS_ALIVE` видно `ᚫ⋄⟡⌁ᛜ`, вместо `MOVE_SPEED` — другой стабильный набор. Внутренние ID и действие операции уже настоящие. Подсказки для зашифрованных полей тоже не раскрывают перевод (может быть нейтральная «Неизвестная запись»). Разные поля остаются визуально различимыми.
3. Игрок нажимает на несколько полей. Срабатывает **неопасное** изменение (например, объект оживает, меняет цвет или начинает смешно подпрыгивать). Луна удивляется, окружающий NPC реагирует:
   - NPC: «Ого! Ты сейчас что сделала с этим деревом?»
   - Луна: «Я понятия не имею. Тут какие-то каракули! Я просто нажала наугад».
   - NPC: «Я, когда в чём-то ничего не понимаю, хожу к Оракулу. У него даже молчание с субтитрами».
   - Луна: «Отлично. Кажется, мне нужны субтитры к самой реальности».
   Реплики ориентировочные; сохранить лёгкость, не создавать длинный обучающий диалог.
4. NPC сообщает, где Оракул (сведения появляются в журнале), но **не телепортирует автоматически** и не запирает игрока в туториале. Игрок может пойти к нему, игнорировать его или заранее найти продвинутые способы взлома.

**Оракул — самостоятельный сказочный персонаж**, не просто меню «перевести». Возможный ранний образ для художника: спокойное светящееся существо, читающее парящие таблички кода как обычные сказки; его можно разместить в маленькой лесной библиотеке/святилище. **Внешность и имя пока проектные, не утверждённые автором**: не генерировать 3D и не добавлять огромную сюжетную линию без отдельной задачи.

## 3. Что даёт Оракул

Оракул помогает Луне научиться читать **технические идентификаторы в уже видимых окнах**. Он объясняет, что строки — язык правил, а не случайные заклинания, и что некоторые поля могут быть опасны. После короткого взаимодействия `technical_language_understood = true`; имена технических параметров и способностей, доступных на текущей глубине `SCAN_DEPTH`, становятся читаемыми на английском CAPS, а при наведении/фокусе показывается **русская** помощь. Удаление шифра не повышает `SCAN_DEPTH`, `MAX_TARGETS`, `RULE_DEPTH` и не выдаёт новые слоты/перки.

**Обязательная независимость трёх вещей:**
- `language_understood`: понятны ли имена уже доступных технических полей?
- `scan_depth`: какие реальные поля может прочитать и изменить текущая палочка?
- `transfer_state`: доступно ли извлечение определённой способности (`OPEN`/`LOCKED`)?

Так игрок, который знает, где находится `WALK` в нечитаемом интерфейсе, может забрать его **до Оракула**, если `SCAN_DEPTH` достаточен. А игрок с понятым языком всё равно не видит и не меняет высокоуровневые поля, пока технически не усилил палочку.

## 4. Структура шифра и правила UX

- Набор знаков для каждого поля строится детерминированно, например по `hash(language_salt + canonical_parameter_id)`. **Фиксировать** `language_salt` в сейве или в конфигурации игры; при повторном открытии одного и того же поля знак не должен хаотически меняться. Разные ID не должны часто коллидировать, скрывать опасные действия и опции подтверждения.
- Шифровать **только системные названия/машинные подсказки**. Кнопки «Сохранить», «Закрыть», «Отмена», «Вернуть», «Забрать», «Передать» и предупреждения о потере сущности **всегда на русском и всегда читаемы**, иначе получится непроходимая ловушка.
- Недоступные по SCAN_DEPTH поля **не выводить** или показывать как неизвестный глубокий слой с замком, но **не смешивать** с gibberish уже доступных полей.
- Перевод не требует дешифровки реального языка программиста. После визита Оракул просто меняет функцию `display_key()` и `tooltip()`; game data остаётся английской.
- Hover и клавиатурный focus показывают одну и ту же русскую подсказку; на геймпаде/тачскрине доступна кнопка `?`/удержание, чтобы не делать игру недоступной без мыши.
- Сложные значения могут иметь русскую семантическую расшифровку в подсказке: `BEHAVIOR_MODE = WANDER` — «Бродить самостоятельно». При расшифрованном интерфейсе поле остаётся английским.
- После первого опасного эксперимента обязательно работает undo/безопасный возврат, независимо от языка и визита к Оракулу.

## 5. Сохранение и повторные запуски

**В рамках одного сохранения:** при получении понимания записать в данные того же save slot стабильный флаг `technical_language_understood: true`; сохранить атомарно и вместе с версией схемы. После перезапуска игры и загрузки **того же слота** расшифровка уже активна — не надо идти к Оракулу снова.

**При новом прохождении / новом слоте:** флаг по умолчанию `false`; сюжет может начаться с непонятного текста вновь. Это **не принудительная прогрессия**: знающий человек может нажать известное поле даже не прочитав его. Не смешивать с глобальным файлом предпочтений `UiLanguage`: язык всего интерфейса всегда русский, независимо от того, понял ли Луна машинный код. Если пользователь отдельно попросит глобальное запоминание *сведений игрока*, хранить его в необязательном журнале подсказок, **не ставить в зависимость разрешение механик**.

**Пример сериализации** (проектный, не существующий сейчас API):
```json
{
  "save_format_version": 2,
  "slot_id": "slot_01",
  "knowledge": {
    "technical_language_understood": true,
    "technical_language_cipher_seed": 317
  },
  "wand": { "SCAN_DEPTH": 2 },
  "property_bank": { "entries": [] }
}
```

**Миграция:** старый `SaveService` прототипа 0.27 использует `FORMAT_VERSION=1` и `Vector3`-координаты. Нельзя тихо дописать флаг в JSON и объявить совместимость с будущей 2D-схемой. Новый 2D save format должен хранить knowledge, банку способностей и позиции, предусматривать backup старого сейва, повторный импорт и тесты на повреждение.

## 6. Тест-кейсы сценария

| Проверка | Ожидаемый результат |
|---|---|
| Первый взлом сразу после разлома | Технические поля зашифрованы, русские вкладки/кнопки читаются |
| Нажатие незнакомого поля | Настоящее неопасное изменение Entity, NPC реагирует, можно отменить |
| Встреча с Оракулом | Появляются `HEALTH`, `IS_ALIVE` и русские tooltip; глубина скана та же |
| Закрыть игру/перезапустить этот же сейв | Расшифровка сохраняется |
| Начать отдельный новый сейв | Машинные имена снова в шифре; русский UI не пропадает |
| До Оракула заранее отобрать `WALK` | Действие разрешено при достаточном скане и `OPEN` |
| До Оракула копией палочки улучшить оригинал | `SCAN_DEPTH` меняется; открываются дополнительные нечитаемые поля |
| Попытка забрать системный код Юки | Если `LOCKED`, показывается русское объяснение и не портится мир |
| Языковой статус и банк при autosave | Сохраняются атомарно и восстанавливаются без потерь |
| Переключение персонажа / цветовой темы | Русские подписи остаются; код раскрыт только по логике истории, а не по палитре |

## 7. Роли в производстве и что генерировать

Для MVP **не требуется** отдельный анимированный 3D-Оракул. Сначала NPC-заглушка с осмысленным диалогом и анимированным мягким свечением/морганием; позже сделать 1 2D-концепт, 1 parts sheet, idle 2–4 ключа, разговор 2 ключа и один маленький эффект смены символов. Нужна **одна** руническая палитра символов для gibberish (SVG/шрифт/кодовые glyphs), а не уникальная картинка для каждого параметра; русские тексты накладывает игровой UI, не запекать их в PNG.

**Текущий статус:** в Godot есть `UiLanguage` с переключателем `en/ru` (en по умолчанию), русские `TAB_RU`, `ProfileService` с журналом открытий и `SaveService`; **нет** реализованного Оракула, шифра имён, slot-aware knowledge-флага и независимой расшифровки в одном save slot. Требуется реализация и проверка.
