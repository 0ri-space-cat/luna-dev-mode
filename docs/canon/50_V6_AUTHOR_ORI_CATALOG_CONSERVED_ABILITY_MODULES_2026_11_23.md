# 50. Прямая авторская идея: конечный Банк отдельных украденных свойств Каталога Ори

**23 ноября 2026.** Продолжение [решения 49 о видовых параметрах и Каталоге Ори](49_V6_AUTHOR_SPECIES_SPECIFIC_HACKING_AND_ORI_CATALOG_PROGRESSION_2026_11_23.md). **Приоритет 50 выше неограниченной выдачи «однажды увиденных» свойств**, которую в виде предложения содержал [сценарий 15](../scenario/15_V6_SPECIES_HACKING_ORI_CREATURE_COMPOSITION_DESIGN_2026-11-23.md). Автор формулирует: «как в Magic Circle — взял одно свойство — всего одно свойство в банке — вложил в существо — всё, больше не можешь, пока не украдёшь у кого-то следующее».

## 1. Прямой принцип [АВТОР]

- Каталог Ори использует **Банк настоящих отдельных экземпляров извлечённых функциональных свойств/модулей**. Извлечение **одного экземпляра** определённой способности у донора даёт **одну единицу в Банке**; оно не открывает бесконечную выдачу этого свойства всем будущим существам.
- Помещение экземпляра в созданное/совместимое существо **расходует именно одну сохранённую единицу**; Банк уменьшается соответственно. Если нужен ещё один такой же модуль для другого существа, придётся **добыть следующий законный экземпляр у другого донора** или вернуть старый в Банк, сняв с прежнего носителя, если это допускается общей системой. Последний вариант **[Р, логичное следствие], не отдельное прямое утверждение**.
- Совмещение нескольких способностей у созданного существа требует **отдельных добытых экземпляров каждой**, поэтому композиции `FLY + SWIM + ELECTRICITY` требуют трёх реальных модулей из допустимых источников. **Одно открытие вида не даёт вечный набор способностей**.
- **Важное толкование:** авторское «одно свойство в банке» относится к **количеству при одном акте изъятия**, а не обязательно к ограничению Банка всего одним слотом. Максимальная ёмкость Банка, правила повторного извлечения, допустимое число копий и UI уточняются при согласовании, а не постулируются.
- Не вводить новый предмет для извлечения: логично объединить **извлечение, Банк и установку в уже существующем `ORI_CATALOG`** (творческий интерфейс обсудить). Состав 16 артефактов не меняется. Базовая палочка продолжает **видовой взлом имеющихся числовых/AI/физических полей**; вопрос о минимальной ранней операции переноса до Ори сохраняет специальную зависимость SWIM.
- Собирать модули игрок может в разное время и в разных регионах, возвращаться к знакомым видам и выбирать, оставить ли способность у доброго донора, извлечь ли у опасного, кому отдать. **Следствие для этики/мира:** донор действительно лишается работы изъятого модуля. Существу нужен предусмотренный безопасный выход/возврат, без бесполезной механики уничтожения питомцев ради уникального компонента.

## 2. Строгая экономика и UX: предложения реализации [Р]

**Транзакция:** `EXTRACT(sourceEntity, abilityInstance)` → донор теряет один функциональный модуль → Банк получает один `AbilityToken` с стабильным ID и provenance. `INSTALL(bankToken, targetEntity)` → Банк теряет тот же один токен → совместимый получатель получает функциональный модуль. Операции подтверждаются одним атомарным действием с Undo, сохранением и отображением реального «1×». При неудачной установке ничего не тратится и донор не теряет модуль. **Копирование токена нельзя подделывать простым сохранением схемы вида.** Точные названия классов и API не канон до внедрения.

- **Каталог хранит шаблон вида/облика** отдельно от **физических экземпляров дополнительных способностей**. Базовая анатомия/обычный способ движения выбранного вида — свойство самой законно создаваемой формы; никакая бесплатная выдача чужих специальных модулей из пустого Банка через смену окраса/шаблона.
- В интерфейсе выбора каждого дополнительного модуля показывать реальный запас: `FLY ×1`, `SWIM ×0` и т. д. После создания питомца списать назначенные модули. При отмене создания до его появления или неудачном сохранении токены вернутся.
- **Переизвлечение у уже усиленного существа** вернуть соответствующий экземпляр в Банк, не создать дополнительный. Вариант на рассмотрении; нужен для ремонта ошибочного эксперимента без повторного отлова редкого донора.
- Разрешённая глубокая метаоперация копирования самих реальных предметов/палочек в Озере и поздний DEVELOPER требуют **отдельного системного правила**: это не автоматическая функция раннего Каталога и не молчаливое обнуление экономии модулей.
- Количество доступных доноров, возобновление мира и гуманность добычи балансировать настоящей экологией: нельзя сделать редкую способность одноразово потерянной и необратимо запертой до самого конца.

## 3. Один принципиально открытый вопрос: SWIM и статус Луны

Ранее автор утвердил **комический перенос SWIM у плавающего существа до DEVELOPER**, с возможностью дать ему новый способ передвигаться/сменить регион/вернуть SWIM. Озеро Дубликатов требует **только подводный путь**, а Луна до DEVELOPER не может просто взломать собственную палочку и бесплатно выдать себе `FLY`/`SWIM`.

Теперь Каталог Ори может **изымать SWIM как конкретный экземпляр и переустанавливать в совместимого получателя**, но ещё **НЕ утверждено**, распространяется ли установка Каталогом:
1. Только на **созданных Каталогом существ**, чтобы один из них стал настоящим пловцом/транспортом; тогда нужно честно решить, как Луна физически минует весь подводный монумент без собственного SWIM; или
2. На **любое подходящее существо**, в том числе Луну отдельным разрешённым способом без самовзлома палочкой, если автор сознательно разрешит это; тогда есть риск преждевременно дать Луне бесплатный `FLY` и другие способности до DEVELOPER.

**Ни один пункт выше не выбран прямой репликой автора.** Предпочесть точное решение вместо искусственного нового зелья Мии, сухого хода или нового 17-го артефакта.

## 4. Остальное остаётся

- Каждому виду — собственные редактируемые параметры, не одинаковые семь табов; универсальные внешние поля и специфическое содержимое «Общего» остаются по 49.
- Каталог Ори остаётся одним оригиналом из 16, художественно цельные живые существа, сохранённые память/идентичность у изменяемых старых NPC.
- Особые задачи для армии защитников/живых опор и персонажные пазлы с озёрными чиби-клонами различаются.
- Лаборатория Мии делает **другое** зелье; одна общая мелодия открывает музыкальные двери; кристальная пещера Озера только подводная; обычный финал кафе не превращается в жёсткую обязательную цепь артефактов.
