> **ПЛАН РЕАЛИЗАЦИИ / 08.11.2026.** Составлен на основании дерева `main` (исходный код прототипа 0.27 и пакет графики, опубликованный 07.11.2026), [арт-индекса](../art/ASSET_INDEX.md) и реальных GDScript-файлов. Это **не** отчёт о проведённой 2D-миграции. Не удалять старую работоспособную версию без прохождения контрольных точек. **Важный конфликт:** `docs/art/HACK_EDITOR_APPROVED_LAYOUT.md` описывает узкую вертикальную панель (~390×610), а показанный автором **последний 2D-концепт** показывает горизонтальнее, широкую панель справа внизу со вкладками по верхней кромке. **Последняя авторская картинка и явные русские подписи имеют приоритет**. Точную сетку размеров следует измерить после получения чистого исходника; пока в продакшен-плане держать адаптивные значения, не копировать старый макет 1:1.

**Объём готовых UI ≠ готовый UI в игре:** много SVG иконок, кнопок, состояний уже есть; сами спрайты не реализуют сохранение, изменение персонажа, анимацию или перевод. Никакой 3D-риги из этих ассетов не образуются автоматически.

## 2. Миграция без разрыва работы: последовательность

### M0 — заморозка рабочего прототипа и миграционная спецификация

- Зафиксировать базовый SHA `main`, сделать тег `pre-2d-migration` / архивный release **перед** любым изменением игровых сцен. Не делать длинно живущую сценарную ветку; отдельный короткий PR на миграцию и последующая интеграция в main.
- Выбрать одну версию Godot, которую реально проверяют локально и в CI; старый код из `Node3D` и тесты 0.27 сохранены как эталон поведения.
- Задать единые данные `WorldTruth` без зависимости от Node3D, и контракт сериализации координат: `Vector2` или абстрактный `WorldPosition2D`; версия формата сейва должна измениться с миграцией, старые 3D-сейвы либо поддержать через мигратор (x,z → x,y при документированном выборе осей), либо честно выдать несовместимость с безопасным backup. **Никогда** молча не считывать старый Vector3 как Vector2.
- **Приёмка:** базовая версия запускается, есть способ вернуться, цель 2D UI и набор файлов зафиксированы.

### M1 — одна маленькая 2D-сцена с настоящей физикой

- `GameWorld2D` + `TileMapLayer` + `Camera2D`, сортировка объектов по Y, collision layers/masks, прозрачные атмосферные слои, `EntityVisualController2D`; 2D-хождение, прыжки/ступени по выбранному правилу высоты и тени.
- У 2D-мира есть **логическая геометрия тайлов/поверхностей**: нарисованный водопад не заменяет `StaticBody2D` или `Area2D`. Переходы между островами/слоями — адресные действия через WorldRegistry. Двери и скрытые мосты физически существуют всегда, а изнанка только влияет на наблюдаемость/подсветку.
- Параллельно оставить кодовый fallback серых прямоугольников, пока ещё нет идеальных арт-тайлов.
- **Приёмка:** герой ходит по 2D-тайлам, камера держит нужный ракурс/масштаб, мост появляется и скрывается от взгляда без изменения коллизии.

### M2 — базовый визуал и оживлённая окружение

- Импорт P1–P4 из [10](10_2D_ASSET_PIPELINE.md): травяные атласы, уступ, водопад 4–6 кадров, кристалл, дерево, светлячки/бабочки.
- Разделить файлы исходника, atlases, runtime-textures и их конфигурацию; собрать две поляны из одной библиотеки.
- Добавить `AnimatedSprite2D`/шейдер с фазами воды, `AmbientSpawner2D` и пул лёгких FX; сделать configurable spawn limits для слабого устройства.
- **Приёмка:** живое окружение без full-screen baked animation, не менее 5 независимых микроизменений в минуту, плавная игра при выключенных эффектах.

### M3 — Луна, риг и сменяемые визуальные части

- Утвердить 1 базовый 2D turnaround из актуального концепта; экспортировать части, собирать `Sprite2D` по точкам рига, `AnimationPlayer` управляет idle/walk/hack/реакциями, глаза/рот меняются отдельно. Невидимые `CollisionShape2D` не зависят от формы шляпы/волос.
- Слои: задние волосы → тело/ноги → руки/предметы → голова/передние волосы/очки → front FX; шляпа и крылья через anchors. Портрет HUD не считать игровым спрайтом Луны.
- **Приёмка:** 30 секунд idle с дыханием, морганием и редкими жестами; управление анимацией работает без прерывистых GIF.

### M4 — овечка, холодильник, дерево и обновление логики команд

- Встроить овечку, холодильник и дерево как `Entity2D` на WorldRegistry/Entity ID; обновить `CommandProcessor` и методы изменения параметров под `Node2D` API.
- Привязать `AI_ENABLED`, `BEHAVIOR_MODE`, `AGGRESSION`, `MOVE_SPEED` к действительным 2D состояниям и PathFollow/NavigationAgent2D; никакой чисто декоративной красной ауры вместо агрессии.
- **Приёмка:** овечка/холодильник живут независимо от игрока, имеют состояния idle, move, react, могут остановиться и продолжить после сейва.

### M5 — редактор: русский UI и раскрытие технического языка

- Новая форма окна по авторскому концепту: справа, адаптивные размеры, мини-портрет **текущей Entity**, вкладки-иконки с русскими заголовками. «Общее» и «Способности» как основные слои; «Поведение», «Облик», «Физика», «Разум», «Отношения», «Ауры», «Реакции», «Теги» — дальнейшие вкладки с русскими заголовками, часть можно группировать, чтобы не перегрузить.
- `UiLanguage` по умолчанию русский. **Все UI-действия, категории, названия предметов/NPC, меню, подсказки на русском**. `HEALTH`, `MOVE_SPEED`, `FIRE_BREATH`, `TRUE/FALSE`, `ID` и подобные машинные значения — технические, на английском; `tooltip` и описание действия — русские.
- Банк способностей — отдельная панель данных: «Забрать», «Передать», «Вернуть», «Отмена». Кнопка **«Сохранить»** обязана иметь реальную семантику: persist текущего состояния/чекпоинт (или явно обозначенный commit режима редактирования); `CommandProcessor` сейчас может применять изменения немедленно, не вводить «применить позже» тайком.
- `EntityVisualController2D` создаёт live-preview выбранного объекта внутри UI через **отдельный безгеймплейный визуальный экземпляр** (Sprite2D риг, не живой AI/entity). Не нужно использовать 3D `SubViewport`.
- **Приёмка:** смена всех семи UI-тем при активном персонаже, читаемость текста при малом viewport, безопасный шифр до Оракула, а затем понимание идентификаторов после сейв/лоад.

### M6 — настоящий перенос способностей

- Создать `PropertyDefinition` и `PropertyInstance`; источники возможностей, логические эффекты, `transfer_state=OPEN|LOCKED`, `required_scan_depth`, и банк в save schema.
- Забрать `WALK` у овечки → та останавливается; отдать холодильнику → движение своими шагами. `FLY` → анимированные крылья из общего sheet + опоры, изменение гравитации и тени. `FIRE_BREATH` → огонь из anchor и collision effect. `GLOW` → окружение освещено.
- Система визуальных рецептов через anchors и классы форм (`box/tall/round/quad`), с отдельными корректировками per-asset. Источник способности не диктует перенос внешних органов.
- **Приёмка:** тесты переноса, конфликтов, обнуления банка, недоступности запретного кода Юки, любых допустимых комбинаций, повторного запуска и отмены команд.

### M7 — изнанка, особые виды зрения и сюжетные первые десять минут

- Единый shader светло-голубых контуров и приглушения мира. Каждый герой добавляет свой отдельный `PerceptionOverlay2D` поверх общей изнанки, без новой палитры тайлов.
- Разлом даёт палочке редактор с нечитаемыми полями, NPC подсказывает про близкого к спавну Оракула. На его полке лежит отдельный **стимпанковский механический Глаз** (`STORY_ORACLE_EYE`), который можно взять только **после физического взлома палочки в разломе**. Глаз надевается и позволяет читать английские технические ключи. Помнить нужно подсказки и просмотренный туториал **в одном слоте**, а не выдавать бессрочную способность читать без глаза. При новом цикле внутри того же слота: быстрый контакт с разломом, без катсцен, затем сразу забрать глаз с полки без разговора.
- Игрок, который **уже знает последствия**, может пользоваться нечитаемым меню без глаза, если палочка взломана. Глаз не меняет `SCAN_DEPTH`, `MAX_TARGETS` и не превращается в скрытый перк; реальный быстрый маршрут при рестарте допускается.
- **Приёмка:** первый цикл показывает вступительный глитч и NPC-подсказку; глаз виден на полке, но до взлома палочки не выдаётся. Глаз надет — поля читаются; снят — gibberish. Обычная загрузка восстанавливает глаз, новый цикл в том же слоте требует только быстрого разлома и получения глаза без разговора; новый отдельный слот снова допускает туториал.

### M8 — UI-интеграция и расширение наполнения

- Подключить имеющиеся `assets/ui/common`, `assets/ui/hack`, `assets/ui/themes`, `assets/characters` и `assets/artifacts` через `Theme`, `NinePatchRect`, `TextureRect`, нужные fallback и реальный runtime-каталог. Скроллинг вкладок при малой ширине, кнопки «Сохранить», «Скопировать», «Удалить» на русском.
- Расширять биомы и семь героев **после** показанного вертикального среза. Тестировать загрузку старой графики в 2D-проекции, но не заставлять игрока использовать 3D-модели.
- Описание в `docs/art/ASSET_INDEX.md` меняется со статуса `prepared` на `integrated` только после конкретного теста в Godot.

## 4. Технические риски и проверка

- Godot 4.x умеет 2D-текстуры и SVG-импорт, но не создаёт автоматически костный риг из изображения. Нужна ручная нарезка и установка pivot/anchors; массовая генерация кадров не заменяет риг.
- Существующие `Node3D` сигнатуры в `HackEditor`, `AbilityService`, `SaveService` и `main.gd` не совместимы с `Node2D` напрямую. **Не менять только тип узла в сцене** без переписывания зависимостей и тестов.
- UI-цвета: семь тем из `assets/ui/themes` — при смене `active_character_id` вся панель меняет оттенок, но семантические ошибки, опасность и подсветка **самого Entity** должны оставаться отличимыми.
- Оригинальные 3D-сцены, звуки и старые референсы сохранять в историческом коммите/архиве. Не объявлять их «удалёнными из Git», если они всё ещё доступны в истории.
- Для замедления/паузы всей симуляции Песочными часами обязательно разнести игровой тайм и независимый UI/time-control, иначе игра застрянет.
- Призма `ART-GL-04` — поздний удобный просмотр **той же** светло-голубой изнанки без палочки в руках. Палочка открывает основной способ, Призма использует тот же рендер и данные, а не вторую реальность; знание позволяет найти её раньше. Глаз Оракула отдельно раскрывает технический язык, PNG Призмы и ID не меняются.

## 5. Чек-лист публикации одного этапа

- [ ] В PR есть фактически созданные `assets/2d` и `.tscn/.gd` файлы; галерея или список будущих путей не считаются интеграцией.
- [ ] CI и минимальный headless-smoke запускают **новую 2D-сцену**, а не старую 3D-сцену, если утверждается готовность миграции.
- [ ] Реальные runtime-сцены читают `assets/prepared_asset_catalog.json` или мигрированный каталог, не только документы.
- [ ] Скрипты не зависят от `Node3D`, если утверждается полный 2D переход. Сейвы валидируются и обратимы.
- [ ] Русские вкладки/кнопки без baked текста, англоязычные machine keys в tooltip и UI; можно переключать темы героев.
- [ ] Есть видео/GIF или несколько реальных скриншотов **из игрового окна** (не композиция из отдельных генераций), которые показывают тайлы, воду, анимацию и TAKE/GIVE.
- [ ] Указаны неготовые части (звук, остальные герои, остальные биомы, редкие свойства) и что использовало fallback.
- [ ] Отсутствуют перки, XP, LEVEL, семикратная обязаловка по сюжетам; проверена свобода раннего знания-first доступа.

**Критерий достижения цели:** любой игрок может запустить именно 2D-прототип, подойти к овечке, забрать `WALK`, дать его холодильнику, увидеть понятные русские вкладки, живую воду/светлячков, сохранить мир и продолжить после перезапуска. До этого этапа честная метка — «2D-ассеты подготовлены, миграция ещё не завершена».
