# LUNA — пиксельный рантайм Godot: текущий код и будущая модульная графика

> **Визуальный канон автора (08.11.2026):** [18 — модульный пиксельный мир](../canon/18_MODULAR_PIXEL_ART_CANON.md). Этот документ описывает лишь текущие возможности кода и безопасный переход; создание 12 отдельных основ травы **больше не требуется**.

## Что уже существует в экспериментальной ветке

- Игровая логическая сетка 64×64 Godot units; новый исходный пиксельный тайл 32×32 может показываться ×2 без изменения Entity, физики и сохранений.
- `scripts/2d/pixel_art_pipeline_2d.gd` загружает корректный атлас, настраивает TileMapLayer и создаёт SpriteFrames из настоящего spritesheet. `tests/test_pixel_art_pipeline_2d.gd` проверяет этот технический контракт.
- Временный `terrain_2d.gd` **пока** ожидает файл `res://assets/2d/eternia/pixel/grass_32_atlas.png` размером 128×96 (12 ячеек). Пока его нет или размер неверный, используется прежний 64px слой.
- Этот старый формат 4×3 — **совместимость промежуточной версии**, а не художественный заказ. **Не генерировать 12 независимых оттенков земли только ради кода.** Следующая техническая партия — поддержать один принятый нейтральный 32px базовый тайл плюс независимые прозрачные декорации.
- Сохраняются временные SVG/PNG персонажей и скал; они не являются утверждённым финальным пиксель-артом. Godot-экран 1280×800 и отдельный CanvasLayer UI пока не переводить слепо в маленький viewport.

## Новый целевой формат

- `ground_base_32.png`: один нейтральный бесшовный PNG 32×32, проверенный в повторении 10×10.
- `decor/grass_tuft_01.png`, `decor/clover_01.png`, `decor/daisy_01.png`, `decor/crystal_01.png` и т. д.: пиксельные PNG с прозрачным фоном и нижней опорной точкой. Декор крупнее клетки допустим.
- `terrain/cliff_face`, `cliff_lip`, `cliff_corner_inner/outer`, `cliff_end`, `steps`: согласованные модульные скалы. В Godot правила terrain transitions/autotiling должны предотвращать неверные стыки.
- `AnimatedSprite2D` и `SpriteFrames` — основа для персонажей: четыре направления, единый canvas/pivot, короткие отдельные циклы `idle/walk`. Временные `luna_puppet_2d.gd` и `creature_visual_2d.gd` с SVG и прикреплёнными конечностями остаются только прототипом, **не финальной анимацией**.
- Nearest для игровых пиксельных изображений; на текущий SVG/HUD глобально не навязывать. Для крупных декоративных объектов — Y-sort, явные collision/occlusion; для симуляции — стабильный seed и исключающие зоны.

## Стандарты проверки

**ImageGen** создаёт художественные исходники. **Код** собирает атласы, сравнивает палитру, проверяет истинную прозрачность, сшивку базового слоя, размеры, импорт и размещение; художественные формы программно не рисует.

Принимать только после проверки в целевом масштабе и на реальном скриншоте Godot. Контакт-листы не выдавать за игровые атласы. Сохранять идентичность Entity, механику взлома, чтение технических ключей, 2D-сейвы и **вертикальный редактор ~390×610** (иконки copy/delete, надпись «Сохранить»).

**История разработки:** `main` остаётся 3D graybox, `feat/2d-runtime-foundation` — экспериментальный 2D. Вносить графику малыми проверенными порциями. Сюжетные документы не переписываются из-за смены техники рисования.
