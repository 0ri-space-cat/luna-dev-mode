# LUNA: Dev Mode — шаблон авторского задания на генерацию сцены

**Использовать вместе с** [мастер-промптом](ENVIRONMENT_ART_DIRECTION_AND_PROMPTS_V1.md) и [атласом референсов](ENVIRONMENT_REFERENCE_ATLAS_V1.md). Шаблон — инструмент подготовки, он **не содержит новых утверждённых уровней**. Можно не заполнять неизвестные поля: будущая модель не должна выдумывать ответы.

## 1. Карточка уровня (заполняет автор)

~~~text
НАЗВАНИЕ / ID ЛОКАЦИИ: [пока свободное имя]
СТАТУС: [идея / эскиз / геометрия согласована / концепт утверждён / интегрировано в Godot]
ЧАСТЬ МИРА: [например, современный город / природный регион / глубина Пустоты]
ТИП ЗАДАЧИ: [STYLE_CONCEPT / LAYOUT_CONCEPT / PRODUCTION_BACKGROUND / SPRITE-PROP / META_CONCEPT]
ТИП КОМПОЗИЦИИ:
  [MAIN_WIDE_34: широкий игровой 3/4]
  [COMPACT_SEMISIDE: компактный полубоковой]
  [META_SPECIAL: Пустота, изнанка, необычный визуальный эпизод]

РЕФЕРЕНСЫ: [REF-01 и другие, максимум 1 главный + 1-2 дополнительных]
ЧТО ОТ НИХ ВЗЯТЬ: [...]
ЧТО ЗАПРЕЩЕНО ПЕРЕНОСИТЬ: [...]
ПРОПОРЦИИ / УГОЛ КАМЕРЫ: [авторское описание; если не указан, сначала концепт]
PIXEL DENSITY / INTERNAL RESOLUTION: [тест/открыто; не выдавать за утверждённый канон]

ГЕОМЕТРИЯ GOOGLE SHEETS: [точный файл/вкладка/ссылка/скрин/экспорт]
  - ширина/высота условной сетки: [...]
  - зоны свободного пола/возможность ходьбы: [...]
  - непроходимые объекты, стены, пропасти: [...]
  - выходы и входы: [направление + ID соседней сцены, если известно]
  - секретные пути: [если автор указал; не делать обязательными без решения]
  - опасности/интерактивные зоны: [...]

ЭСКИЗ SAI: [приложенная картинка/файл]
  - что находится слева/справа/сзади/спереди: [...]
  - подписи и функциональные детали автора: [...]
  - главная точка внимания: [...]
  - что специально должно остаться пустым: [...]

ПЕРСОНАЖ: [никого / CLASSIC / CHIBI / только отдельные NPC по списку]
ВАЖНЫЕ ОБЪЕКТЫ: [точный список]
ЧЕГО В КАДРЕ БЫТЬ НЕ ДОЛЖНО: [точный список]
ВРЕМЯ СУТОК / ПОГОДА: [...]
ПАЛИТРА ЗОНЫ / НАСТРОЕНИЕ: [...]
ИСТОЧНИКИ СВЕТА: [...]
ЗАКОН НАБЛЮДЕНИЯ / МЕТАЭФФЕКТ: [не нужен / точный механизм из V6]
ВЫХОД: [одна концепт-картинка / фон / ассеты по отдельности / несколько явно заданных состояний]

ОТКРЫТЫЕ РЕШЕНИЯ: [оставить пусто / явно перечислить]
~~~

**Если автор пока нарисовал только арт-набросок SAI, без табличной геометрии**, модель может сделать **стилевой концепт**, но не обещать соответствие конкретным коллизиям. Если имеется сетка без художественной расстановки, модель не вправе придумать за автора важные здания и NPC как утверждённую карту.

## 2. Порядок подготовки генерации

1. Открыть [V6](../canon/20_V6_AUTHOR_ONLY_BIBLE.md) и убедиться, что используемые законы мира не устарели.
2. Прочитать **главный и дополнительный** REF вместе с предупреждениями «чего не копировать».
3. Определить A/B/C-камеру, не подменяя главный игровой мир одноосевым платформером.
4. Выписать из Google Sheets физические границы и переходы; из SAI — композицию и положение объектов.
5. Подставить [английский мастер-промпт](ENVIRONMENT_ART_DIRECTION_AND_PROMPTS_V1.md) + один точный модуль + заполненный brief.
6. Сгенерировать **один** концепт; проверить семь вопросов ниже; после замечаний автора исправлять конкретные ошибки, не перерисовывать всю карту по новому выдуманному сценарию.
7. После утверждения концепта отдельно обсудить экспорт **фона/foreground/динамических объектов/коллизий** и тест в Godot.
8. Пометить источник каждого нового элемента: **авторская геометрия, авторский SAI, подтверждённый референс, предложение модели**. Последнее не записывать в канон без одобрения.

## 3. Быстрый чек-лист принятия

- [ ] План SAI и Google Sheets сохранён.
- [ ] Есть достаточно пола и понятен проход по двум осям, если зона основная.
- [ ] Ракурс соответствует конкретному типу A / B / C.
- [ ] Луна не стала гигантской, младенцем или другим персонажем.
- [ ] Все объекты и Луна нарисованы с одинаковой плотностью пикселя.
- [ ] Матовая палитра без мыльного blur, грязного dithering и лишнего неона.
- [ ] Мир остаётся современным магитехом, а не средневековой фэнтези-деревней.
- [ ] Не добавлены чужие обязательные секреты, NPC и игровая география.
- [ ] Production-фон отделим от NPC, персонажа, HUD и hackable props.
- [ ] Возможен реальный переход в Godot, а не только красивый скриншот.

## 4. Статусы для GitHub, чтобы не путать концепт с реализацией

- **authored_layout** — автор нарисовал клеточный план/эскиз SAI.
- **concept_generated** — есть сгенерированная картинка, но она ещё не принята.
- **art_approved** — автор одобрил художественный ракурс/палитру.
- **sliced_for_game** — производственный фон/предметы разделены по слоям, проверены размеры и alpha.
- **integrated** — scene/resources реально подключены к Godot.
- **tested_playable** — проверены коллизии, маршруты, перспектива, камера, загрузка, смена цвета и взаимодействия.

Названия — **предлагаемая организационная метка**, не текущий статус уже существующих уровней.

## 5. Как передавать карты из Google Sheets и SAI

- Не полагаться только на цвет ячейки: внутри grid полезны стабильные типы пола/стены/перехода/системного объекта, либо экспортированная таблица с легендой.
- Не смешивать **связи сцен** и **внутрисценовую геометрию** без явного ID. Можно оставлять стрелки и ссылки между вкладками, а агент при импорте должен проверять их направления.
- Картинку SAI брать в качестве **композиции и расположения объектов**, а не автоматически превращать её набросочные линии в точные CollisionShape2D.
- Генерация пиксель-арта не создаёт сама собой правильные слои, навигацию, физику, хитбоксы, точную информацию о секретных проходах или работающую смену FOLLOW/LOCKED.
- После визуального утверждения сделать тест с реальным CLASSIC/CHIBI спрайтом на нужном уровне масштаба — единый рисунок должен оставаться единым и в движении.

**Если задумка не определена автором, оставлять её открытой.** Этот шаблон нужен, чтобы будущие модели красиво воплощали готовую задумку, а не заполняли Этернию самостоятельно придуманной картографией.
