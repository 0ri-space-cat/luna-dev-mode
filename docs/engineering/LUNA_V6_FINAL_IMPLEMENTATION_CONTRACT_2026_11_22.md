## 1. Условия приемки всей игры

Выпуск/релиз недопустим, пока не работает хотя бы один **связный** проход старт → открытые биомы → свободный вечер кафе → титры/возврат, а также оба глубинных пути без сюжетных флагов. Каждое изменение должно пройти:
1. редакторскую проверку, что закон мира воспроизводится у двух разных типов сущностей и в двух местах;
2. проверку разных порядков знакомства и системных сочетаний;
3. сцены с реальными коллизиями в Godot, а не только утверждение в Markdown;
4. сохранение/загрузку до и после действия и отказа в доступе;
5. проверку FPS и UI с нормальным/большим количеством активных объектов;
6. контраст и доступность эффектов в pixel-art сцене.

**Целевые профили теста:** новичок с PLAYFUL; игрок с предметами, но без DEVELOPER; опытный с DEVELOPER; человек с известным лесным ключом в первые 20 минут; другой управляемый профиль; игрок после кафе; игрок после объединения прото-Луны; игрок с аномальными параметрами тела; игрок с сотнями клонов. Секретам не требуется официальная фиксация посещения в квестлоге.

## 3. Данные: один формат настоящей карты вместо наследования прототипа

Создать **production authoring** рядом с тестовыми данными, например:
- `game/data/production/locations.json`
- `game/data/production/entities.json`
- `game/data/production/artifacts.json`
- `game/data/production/profiles.json`
- `game/data/production/schedules.json`
- `game/data/production/global_keys.json`
- `game/data/production/secret_contracts.json`

**Не переименовывать сразу** текущие `game/eternia/world.json` с краткими ID `ISLAND/LAKE/DEBUG` и `DEV_LOCATIONS.json`: это разные прототипные редакторы. Новый runtime читает финальные ID из **нового валидируемого каталога**. После подключения production shell прототипная карта остаётся тестовым стендом или уходит в archive отдельным PR, не смешиваясь с настоящими сохранениями.

**Форма элемента реестра (схема выбранная для реализации):**
```json
{
  "id": "ET_DUPLICATE_LAKE_CAVERN",
  "kind": "WORLD_LOCATION",
  "scene": "res://scenes/production/duplicate_lake_cavern.tscn",
  "discovery": "world",
  "required_access": "PLAYFUL",
  "entries": {
    "dry_path": {"position": [0, 0], "safe_radius": 20},
    "underwater_exit": {"position": [120, 24], "safe_radius": 20}
  },
  "visible_on_public_map": true,
  "has_return_anchor": true
}
```
Это **пример полей будущего production JSON**, а не заявление, будто такая PackedScene уже существует. `location_router_2d.gd` сейчас ожидает другой конкретный формат `entries`/прав; нужен адаптер/миграция и тест схемы, а не замена данных на несовместимый JSON до реализации загрузчика.

**Единый типизированный адресный реестр:** `ET_*` и `META_*` — разные семейства зарегистрированных **LOCATION ID**, но оба могут быть адресами реального перехода по `TELEPORT` или совместимой двери, если есть безопасная точка входа и ReturnAnchor. `META_WHITE_VOID` показывается игроку при посещении Белой Пустоты и доступен по точному имени **даже до первого посещения**. `GAME_MODE` — системный ENUM, `GAME_FRAME` — системный TARGET, `OUTSIDE_COLLISION` — его поле. `ET_DUPLICATE_LAKE` — Feature ID, **не локация**. `ET_CRYSTAL_UNDERSIDE_PASSAGE`, `ET_UNDERSIDE_REFUGE_01` — настоящие новые секретные сцены; `BRIDGE_UNDERSIDE_A` — геометрия/объект. `ET_WATERFALL_BEYOND_THIRD_BRIDGE` — устаревший алиас. Искусственный пароль `SIMULATION_BOUNDARY` исключён из production. Список в [реестре](../drafts/V6_LOCATION_ID_REGISTER_2026_11_22.md).

**Стабильные ID существ:** префикс типа + локальный UUID/инкремент ID внутри сейва, глобальный уникальный индекс; копия всегда новый ID, предмет в инвентарном слоте сохраняет собственный Entity ID и owner/position. Удалённые сущности хранятся в `deleted_ids`/tombstone. Никакой мгновенной генерации чужого профиля по `switch_profile`.

## 4. Каталог артефактов и инвентарь без Свитка

Production `artifacts.json` должен содержать **строго 16 ключей** (сохранить стабильные имена, а не номера старых позиций):

```json
[
  "TIME_BUTTON", "OBSERVATION_CAMERA", "RUNE_MONOCLE", "GRAVITY_COMPASS",
  "GRAVITY_GUN", "PORTAL_GUN", "HOURGLASS", "YUKI_CONSOLE",
  "LUNA_ROOM_DOOR", "MIA_POTION", "TOFFI_LANTERN", "LEIA_HEART",
  "ORI_CATALOG", "PRISM", "DIGITAL_EYE", "PIXEL_GLOBE"
]
```

**Запрещённый/исторический ID `SCROLL`** — не имеет игровой сцены, рецепта, слота, иконки или инвентарного предмета. Существующее `game/eternia/content_pool.json` следует привести к 16 видимым карточкам и актуальным описаниям; старые сохранения, содержавшие только кандидатную карточку «Свиток», не должны падать при загрузке. Свиток не следует маскировать новым «контейнером серий»: **составные заклинания находятся в самой палочке**.

**Исходные владельцы персональных позиций:** YUKI_CONSOLE → Юки; MIA_POTION → Мия; TOFFI_LANTERN → Тоффи; LEIA_HEART → Лея; ORI_CATALOG → Ори; DIGITAL_EYE → Они. Луна не получает вторую физическую копию по флагу дружбы; её начальная палочка **вне каталога 16**. Остальные 10 самостоятельных предметов и первые регионы находок уже выбраны в библии 35 и главе 25. Каталог не равен наградному квесту «найти все 16».

**Валидатор:** категории `standalone / personal / unique_scene`; конкретный owner, уникальный spawn, pickable mode и разрешённое действие; выпадение/подбор не должны терять исторический ID. Инвентарь показывает именно зарегистрированные Entity, а не копии иконок в каждом профиле.

## 5. Палочка: право, операции, UI и безопасность

**Команда запроса взлома:**
```text
request_hack(actor_id, wand_id, target_id, target_kind, operation)
 -> Result(OK | ACCESS_DENIED | OUT_OF_RANGE | BAD_TARGET |
           INVALID_FIELD | UNSAFE_STATE | BUSY)
```

**Порядок проверки**: существует ли действительный actor/wand → кому принадлежит выбранный инструмент → геометрическая/системная разрешённая цель → PLAYFUL/DEVELOPER → тип поля/диапазон → безопасная транзакция. Отказ не меняет сущность и не расходует ресурс. Не отправлять editor command напрямую в `EntityRecord`, минуя `WandEditPolicy2D`.

**Семь вкладок на UI:** Общее / Облик / Физика / Разум / Поведение / Отношения / Способности. Данные из типизированного реестра, не 400 жёстких полей вручную в каждом NPC. Для скрипта `SpellProgram2D` сохранять **1–8 операций SET, ADD, MULTIPLY, TOGGLE**, один snapshot / one Undo. Первоначальная цена `6 + 2*n` маны, максимум маны 100, регенерация 4/сек вне блокирующих состояний. Клиентский редактор должен показывать сумму операций и причину отказа; не выполнять произвольный GDScript пользователя.

**Разлом стартового острова** открывает PLAYFUL только для конкретной палочки. **Озеро** создаёт вторую реальную палочку и допускает изменение доступа одной палочкой другой → DEVELOPER для **одного конкретного экземпляра**. При замене экипированной палочки старая физически выпадает, не уничтожается. Самовзлом при удержании TAB около 2 секунд в пустую сторону открывает собственную карточку; `APPEARANCE_STYLE` не влияет на хитбокс. Любая системная правка собственного `SCALE` проходит коллизию безопасного места выхода.

**Приоритет TAB-цели:** валидный близкий объект мира > конкретный HUD-элемент, если герой физически подошёл к экранному региону > внешняя GAME_FRAME, **только когда она сознательно отдельно сфокусирована в оконном режиме**. Мышь на обычном HUD не даёт дальнего редактирования из середины карты. Предмет внутри занятого слота проверяется по его ID, без «предмет считается панелью».

## 6. Внутриигровой WINDOWED, виртуальный desktop и настоящий GAME_FRAME

**Критический художественный факт:** `GAME_MODE` — **глобальный внутриигровой enum** `FULLSCREEN | WINDOWED`; реальный Godot window/display остается в штатном состоянии. Значение `WINDOWED` **рисует окно Этернии поверх нарисованного виртуального рабочего стола** внутри приложения. Отдельный UI-настройщик может изменить этот параметр с самого начала. Это обычная настройка, и **само переключение ничего не открывает**.

**Намеренная команда** `focus_outer_frame` выделяет **нарисованную** границу окна. При PLAYFUL: стандартный краткий отказ без имени цели. При DEVELOPER: TAB открывает
```text
TARGET = GAME_FRAME
CLASS = SYSTEM_OUTER_VIEW
GAME_MODE = FULLSCREEN | WINDOWED        # read-only отражение общего enum
OUTSIDE_COLLISION = BLOCKED | PASSABLE  # редактируемое состояние рамки
```
**Физический переход** в `META_DESKTOP` возможен тогда и только тогда, когда `GAME_MODE=WINDOWED`, `OUTSIDE_COLLISION=PASSABLE` и активная Луна **действительно пересекла** валидный коллизионный периметр окна. Отдельный системный путь из лесного терминала позволяет тому, кто **сам знает имена**, установить `GAME_MODE`/поле `GAME_FRAME` даже без DEVELOPER-палочки: свойство консоли — доступ по знанию. Это не означает права TAB-взлома произвольного HUD с PLAYFUL.

**Иллюзия рабочего стола и личные данные:**
- По умолчанию — **вымышленный desktop** в той же Godot-CanvasLayer с правдоподобным фоном/панелью/иконками, не настоящее рабочее окружение ОС и не реальный alt-tab.
- Опция `DESKTOP_BACKGROUND_SOURCE = SYNTHETIC | USER_WALLPAPER | USER_IMAGE | PRELAUNCH_CAPTURE` регулирует только текстуру фона, не игровое состояние. `USER_IMAGE` — файл, который пользователь **сам выбирает**. `USER_WALLPAPER` — чтение обоев только при согласии/разрешении. `PRELAUNCH_CAPTURE` — исключительно если поддерживается **launcher до запуска игры и отдельное явное разрешение**, без него не заявлять реальный захват «перед запуском».
- Никогда не делать скрытый снимок экрана, сканирование чужих приложений/уведомлений/файлов, загрузку изображения в сеть и ответы героини с реальными секретами пользователя. Хранение импортированного изображения локальное, удаление/сброс доступны, любой отказ даёт **SYNTHETIC** без потери метахода.
- Не делать синтетический desktop «предельно пародийной» картинкой, которая разрушает эффект неожиданности. Но никакой графический обман не включает реальные приложения OS.

**Проверить:** переключение внутриигрового enum при настоящем fullscreen, разные разрешения/DPI, мышь/геймпад, виртуальная рамка, отказ PLAYFUL, DEVELOPER-взлом, заданный через лес параметр GAME_FRAME, физическое пересечение, возврат в мир, отсутствие доступа к ОС, импорт фона, отказ от разрешений, приватность, безопасный fallback.

## 7. Лесная консоль: универсальные типизированные параметры и адреса

`ET_FOREST_SERVICE` существует с первого запуска как географически скрытая **настоящая системная консоль**, не личная консоль Юки. **Не строить отдельную пару `SIMULATION_BOUNDARY = WHITE_VOID`**: она отменена прямым авторским ответом и не зарегистрирована в игровом реестре.

**Общий контракт операций** (все проходят type/range/safe destination validation):
```text
LOOKUP(property_name)       # знает тип поля, только ПОСЛЕ точного имени
READ(target_id, field_name)
WRITE(target_id, field_name, typed_value)
TELEPORT(location_id)
```
Имя `property_name` и, если нужно, `target_id` вводятся **вручную**. Правильное имя из общего `GameParameterRegistry` позволяет выбрать bool `TRUE/FALSE`, enum-список, INT/FLOAT, адрес `LOCATION_ID`, ссылку на Entity и другие заранее типизированные данные. **AutoSuggest известных типов — да; автосписок неизвестных полей, секретных адресов и «похожих» ключей — нет.** Реестр охватывает **любой настоящий параметр игры, для которого определена безопасная системная операция**; добавление нового объекта/поля не требует отдельной команды в сценарии терминала. Отсутствующее поле показывает понятную ошибку, не читает файловую систему/GDScript.

**Адрес как знание:** при входе в каждую зарегистрированную локацию в HUD ненавязчиво показывается настоящий ID. При посещении Белой Пустоты **обязательно** отображается `META_WHITE_VOID`. Игрок может скопировать его, запомнить или узнать от другого игрока и ввести
```text
TELEPORT META_WHITE_VOID
```
Это работает **даже с PLAYFUL, ещё до Озера и кафе, независимо от `visited_meta`**. Консоль делает безопасный переход в тот же регион и настоящую позицию входа с ReturnAnchor. Никакой «зачислен в финал» проверки.

**Дверь тоже использует настоящий Location ID:** любая **совместимая** реальная дверь с `TARGET_LOCATION` принимает `META_WHITE_VOID`, потому что реестр умеет приводить такой ID к безопасному специальному MetaSceneRouter. Игроку нужно узнать ID и иметь настоящую возможность изменить целевую дверь; нет произвольного запрета `META_`. При открытии/пересечении двери срабатывает **физический переход**, а не моментальное авто-кинематографическое завершение сюжета.

**Знание GAME_FRAME:** через терминал можно вызвать `WRITE(GAME_MODE, WINDOWED)` и `WRITE(GAME_FRAME, OUTSIDE_COLLISION, PASSABLE)` (реальный интерфейс задаёт цель/поле отдельными типизированными элементами, этот синтаксис демонстрационный) и затем **самостоятельно выйти через нарисованную рамку**. По-прежнему нет случайного выхода от одноразового переключения настройки.

**Различать валидатор:** `WORLD_LOCATION`/ `META_LOCATION` — **оба** могут являться `LOCATION_ID`, если مقصدен узел регистрации допускает safe spawn. Дверь не принимает `WHITE_VOID` как произвольное необъявленное слово, поскольку действительный ID — **`META_WHITE_VOID`**. Системная телепортация не предполагает произвольный GDScript и не меняет реальную ОС.

## 8. Озеро Дубликатов: состояние, физика и предохранители

**События на входе в воду:**
```text
ON_ENTER_WATER(actor_id):
  if actor_is_main_luna:
    attempt_spawn_chibi_clone(immediate=true)
    schedule_attempt_every(5.0 seconds of active game time)
ON_EXIT_WATER(actor_id):
  cancel_timer_and_reset_sequence()
```
Первый клон немедленно, последующие каждые 5 секунд **попытки**. Сохранение после выхода не превращает сброс последовательности в двойное клонирование. Для других предметов и существ — отдельный контактный `DuplicateRule`, не автоматическое копирование всех инвентарных предметов у Луны.

**Entity-контракт:** каждый клон получает новый ID/position/body/physics/behavior, ссылку на источник `duplicate_origin_id` и **обычное независимое состояние**. Его постоянный профиль не добавляется в список семи. Он не может носить уникальные подарочные предметы автоматически и не наследует системные права DEVELOPER как бесконечный инструмент. `CLASSIC`/ `CHIBI` у основной Луны никак не превращает клона в восьмого героя; изображение клонов CHIBI.

**Предел для первого производственного прототипа:**
- до **32** полностью физически обновляемых клонов в активной пещере;
- до **256** сохранённых автономных клонов источника в пределах сейва, включая off-screen сериализованные;
- максимум **8 ожидающих попыток появления** при физически занятой точке;
- после реального переполнения видимое сопротивление воды/всплеск и отсутствие нового spawn, пока не появится место/вместимость; ни одна уже рождённая копия **не исчезает молча**.
- в off-screen зоне симуляция событий дешёвая и детерминированная; при возвращении в видимую область восстановление прежнего ID, без дубликата.

**Важно:** одновременно требовать математически бесконечный spawn и конечный бюджет памяти невозможно. Это выбранный **видимый физический предел вместо тайного удаления**. Точные 32/256/8 — профилируемые константы; менять их можно по тестам FPS/4 MiB сейва без художественной переписки закона. Десятки минут в воде, перезапуск и изменение Time Scale обязаны проходить без раздувания JSON до отказа. Палочка, действительно вошедшая в воду как физическая сущность, копируется отдельно. Две палочки могут взаимодействовать через тот же регистр команд без самовольного открытия прав у любой новой копии.

**Обратная дорога:** сухой путь к пещере нужен даже без `SWIM`; подводный — дополнительный. При застревании, отказе spawn или выпадении палочки доступен безопасный реальный возврат к ближайшей опоре/бережку.

## 9. Взгляд и мосты, водопад

**Общая проверка наблюдения:**
- `BRIDGE_I`: collider=true, render=false, независимо от глаз/камеры.
- `BRIDGE_II`: collider=NOT `controlled_actor_is_looking_at_bridge`. При закрытых глазах героя collider=true; игрок видит игру как обычно. Отдельная дверь может иметь **обратный** закон. Не проверять mouse cursor вместо глаз героя.
- `BRIDGE_III`: collider=NOT `active_camera_viewport_intersects_full_bridge_support_geometry`; поддержка включается только когда **ни одна активная часть физической полосы моста не видна внешним игроком**. `LOCKED` не замораживает движение, `FOLLOW` вновь может убрать опору; безопасная нижняя полка/ReturnAnchor не дают softlock.

**Анти-облёт водопадом:** специальный узел `WaterCurrentField2D` с **действительной направленной силой** на объекты и актёров в физическом объёме, с анимацией потока. В зоне верхнего/нижнего облёта такой сильный направленный поток, что обычный FLY/верховой перенос физически сносит к спасательному нижнему участку. В узком защищённом створе самого мостового перехода струя отсутствует либо имеет недостаточное боковое давление. Не использовать условие `if not bridge_solved: disable_fly()`. Мощность силы относительно базовых MOVE_SPEED/FLY корректируется на greybox; **одинаковое правило применяется ко всем совместимым динамическим телам**, с учётом массы и допустимых способностей. Отдельные глубокие телепортации по реально известным адресам не являются полётом и не блокируются флагом непосещения.

**QA:** полёт сверху/снизу, порталы, гравитация, Гравипушка, превращения SCALE, клонированные предметы, езда на существе, разные размеры viewport, смена FOLLOW посреди перехода, save/load на защищённом берегу и откат после падения. Правильно разгаданный мост должен проходим физически; не превращать его в «две секретные клавиши в определённом порядке».

## 10. Профили и расписания без клонирования персонажей

**Таблица игрового профиля:** `profile_id` (из фиксированных 7), `entity_id`, `home_location_id`, `current_location_id`, `current_position`, `personal_tool_entity_id`, `story_known`, `profile_prepared`, `active_controller`. У героев уникальные Entity ID и личные предметы. Каждый NPC продолжает жить по правилам до/после чужого управления.

**ЗАКРЫТА ПРОБЛЕМА «как вернуться, если персонаж без палочки»:**
1. До DEVELOPER любые попытки взлома портретов обычным PLAYFUL дают отказ.
2. После личной истории профиль **подготовлен**, но не активирован автоматически.
3. Первый успешный DEVELOPER-взлом портрета Луной регистрирует **`PROFILE_CONTROL_AUTHORITY` в доверенном контроллере игрока** (однократное осмысленное системное открытие). Это **не** DEVELOPER-уровень чужих личных инструментов и не новое открытие метафинала.
4. После этого все подготовленные профили можно выбирать **через тот же HUD-портрет** от лица текущего активного героя; возвращение к Луне всегда доступно, не требуется наличие Луной палочки в руках другого персонажа. Защищённые другие HUD-поля всё ещё проверяют их собственный DEVELOPER-источник.
5. Смена управления вызывает **remote takeover** настоящего тела в его реальной позиции. Предыдущий герой остаётся на месте и получает локальный автономный режим. Если новая локация неактивна, транзакционный `LocationRouter2D` монтирует её с действительным безопасным spawn; не появляется второй экземпляр.
6. Если актёр стоит в воде, падает или входит в виртуальный внешний слой, переключение либо ждёт ближайшего устойчивого шага, либо предлагает явный безопасный переход в состояние, не нарушающее физику и сохранения; нельзя терять тело при отмене/срыве.
7. При повторном входе в Meta сюжетное объединение остаётся возможным только с **настоящей Луной**, другой профиль может осмотреть сцену и вернуться к ней без потери данных.

**NPC Schedule**: 3–4 суточных блока, home + 2–3 региональных занятия, обратимые реакции на погоду/события, путь по реальной карте, offscreen сохранение времени и состояния. Схема может иметь `slots: [{period:"morning",location:"...",activity:"..."}]`; это **не телепортирующее расписание**: маршрут и arrival учитываются, герой при недостаточном времени пропускает план и остаётся живой сущностью. Точные 2–3 занятия каждого друга уже заданы в [главе 35](../canon/35_LUNA_V6_FINAL_GAME_BIBLE_FOR_IMPLEMENTATION_2026_11_22.md) и сценах II–VII. Игрок, пришедший позже, встречает последствия, а не повторяющуюся первую постановочную реплику.

## 11. Социальный финал, прото-Луна и нелинейный порядок

**Кафе постоянно существует в `ET_LUMA_CAFE`**. Это не сцена, которая создаётся после семи личных историй. Вечер может собраться, если согласно действительным часам и расписаниям в кафе есть Луна и хотя бы один знакомый значимый собеседник; остальные заходят/уходят естественно. Событие `STAY_FOR_THE_EVENING` — **добровольная реплика/действие Луны у стола**, доступное по присутствию живой компании; эта реплика **не называется «начать финал»**. После диалогов игрок сознательно решает **завершить вечер**, запускаются обычные титры. Эмоциональные реплики зависят от действительно встреченных друзей/происшествий, не от списка «7/7». Чтобы не выдавать титры за один случайный завтрак, взаимодействие подразумевает естественный вечерний ритм, а не автоматическую реакцию на первый вход.

**Голубой след перед обычными титрами** привязан к самой постановке дружеского вечера, но не запускает новые мета-законы. После уже завершённого метафинала воспроизводится **записанный прежний след** без фразы «спаси меня прямо сейчас». Ни нормальная развязка, ни объединение не стирают друг друга.

**MetaSceneRouter** получает `entry_source=FOREST_CONSOLE | GAME_FRAME`, `original_profile_entity_id`, `return_anchor`, `proto_luna_joined`, `scene_id`. Оба источника ведут в **тот же единый набор внешних состояний**. Отдельная прото-Луна остаётся после входа реальным сюжетным субъектом до добровольного объединения, **собственным Entity ID**. Объединение выполняется атомарной транзакцией: два согласия, флаг объединения, обновление памяти современной Луны, прекращение второго отдельного NPC, короткая визуальная Омега-Луна. Возврат в любой обычный мир не перезапускает финал. Порядок мета → кафе поддерживается; дневник и реплики не притворяются, будто игрок прошёл все главы.

**После финала:** **настоящая автономная Луна** через примерно 15 секунд бездействия физически уходит из кадра и делает небольшие, но системно осмысленные изменения мира; игрок может летать свободной камерой и найти её, вернуть управление. После каждого следующего запуска с завершённым метасюжетом одно детерминированное случайное причинное событие уже изменило живой мир. Системы и тесты раскрыты в §11.1 ниже. Пользователь вправе ограничить/отключить автономию в настройках.

### 11.1. Автономная Луна, FREE_CAMERA и события после запуска

**Триггер:** `META_JOINED == true`, около **15 секунд без физического ввода**, безопасная локация, активная Луна, нет открытых модальных окон/боевой угрозы/необратимого падения. После триггера `CameraFollowLock2D` фиксирует текущий viewport; `PostMetaLunaAutonomy2D` принимает локальное тело Луны и планирует маршрут **по действительной геометрии** за край viewport. Сохраняются ID/координаты/настоящий активный мир; нельзя телепортировать героиню «за сцену» только ради трюка. Параметры поведения персонажа остаются частью общих законов мира.

**Планировщик маленьких целей:** с учётом ближайших сущностей и ресурсов выбирает `GOAL` из подходящих действий (сделать занятному объекту другую привычку, помочь зверьку пройти, оживить смешную вещь, собрать чиби на импровизированную встречу, чуть переставить указатель), затем исполняет реальные `CommandProcessor`-команды с разрешёнными проверками, реакциями NPC и сохранением. Избегать «три катсцены на рандом» и не разрешать убийства/стирание уникальных предметов/принудительное объединение/закрытие выхода. Ошибка плана отменяет только ту попытку, не весь постгейм.

**Свободная камера:** `FREE_CAMERA` после объединения — независимая точка обзора, input перемещает **камеру**, Луна продолжает AI в физическом мире. Межрегиональная камера грузит настоящие соседние области без клонирования Луны; при обнаружении героини видны её **реальные действия и последствия**. `TAKE_CONTROL` мгновенно возвращает ввод **тому же Luna entity ID**, камера плавно возвращает FOLLOW. При обычном вводе из idle — то же. Режим не даёт выдуманных координат тайников, не нарушает закон камеры моста III: наблюдатель — действительный viewport свободной камеры.

**Событие на каждом следующем запуске:** при `META_JOINED` сохранять `meta_session_index` и уникальный `luna_event_id` для текущего запуска. До первого кадра новой сессии один раз выбирать по воспроизводимому seed **одно событие из достижимого, безопасного текущего мира**, проигрывать его через те же игровые Entity/Command операции, сохранять состояние и короткий локальный след/реакцию NPC. Не увеличивать счётчик от перезагрузки сцены, паузы или загрузки сейва **в той же сессии**; восстановление после crash не дублирует действие. В закрытой программе нет фонового процесса и доступа к реальным файлам.

**Пользовательские настройки:** `LUNA_AUTONOMY_MODE=FULL|LIMITED|OFF`, `FREE_CAMERA` по осознанному действию; ограниченный режим уменьшает дальность/число изменений, OFF не меняет сам факт добровольного объединения. Настройки не выдают метасекрет раньше встречи и не допускают поломку мира.

## 12. Время и откат: три разных действия

1. **Global clock:** сутки/приливы/расписания, отдых двигает время вперёд. `WorldClock2D` уже существует; локальные часы региона хранятся отдельно.
2. **Песочные часы:** время `SLOW/NORMAL/FAST = 0.5/1/2`; не STOP. Физика сохраняет предсказуемую последовательность событий и честное совпадение эффектов.
3. **Кнопка времени (поздняя, ET_FORGOTTEN_SERVICE):** назад до **60 сек** активной локации и управляемого персонажа через bounded timeline; **кулдаун 60 сек реального времени** не откатывается Кнопкой. Не возвращает друзьям знакомство «до встречи», не копирует системные награды и не удаляет объединение. После перемотки валидировать все Entity ID, клоны, двери, физические коллизии. Аварийная recovery/undo отдельная и бесплатная.
4. **Настоящий стоп** существует только у экспериментальной заморозки редактора с управляемой героиней; никакой отдельный новый артефакт его не создаёт.

**Транзакционные границы:** `world_epoch / local_timeline / durable_knowledge / profile_authorizations / meta_state`. Локальная перемотка редактирует лишь разрешённый local epoch и позиции, с проверкой, что сохранение/ссылка не нарушает глобальные профили. Для длительных симуляций не хранить каждую частицу/каждый пиксель на 60с; хранить компактные обратимые физические снимки/команды внутри бюджетов.

**S5. Мир и уникальные предметы:** лес/Fairy Realm, острова, прибрежные циклы, 16 артефактов с намеченными первыми регионами, сюжетные профили, движущийся город и невидимые гиганты. Успех: знакомые инструменты дают неожиданные честные пересечения в двух регионах.

**S6. Художественная и социальная полировка:** полноценная композиция пиксель-арта, зональная матовая палитра, понятные диалоги, вечер в кафе, две версии финала по порядку входа, Омега-Луна, Призма-3D-гэг; **постмета FREE_CAMERA, побег Луны за кадр после 15 секунд и одно осмысленное событие на новый запуск**. Успех: обычный путь сам по себе приятен, глубокий слой практически не обнаружим без инициативы, в Этернию хочется вернуться.

**Никаких дат релиза и обещанных 40 часов до плейтестов.** Это порядок строительства, не сюжетные главы.

## 15. Результат интеграции и запреты

**Готовым к коду** называется этот дизайн-контракт. **Реализованным** считается только код после Godot/CI/GUI тестов. По мере работы не требовать у автора заново утверждать Свиток, число артефактов, два пути к Белой Пустоте, большую стилистику, модель профилей, запрет раннего GAME_FRAME и базовые законы мостов. Для художественных точных Sheets/SAI карт использовать авторские материалы, не делать случайную генерацию «ну пусть так будет» вместо авторского рельефа.

**Красные флажки на ревью:** появились XP/perks или девять обязательных глав; удаляется клон ради FPS; тайно отключается FLY; внутриигровое WINDOWED подменено настоящим режимом ОС; обои/скриншот берутся без согласия; простое переключение GAME_MODE сразу выводит в Meta; лесная консоль стала квестовым паролем или дверям запрещён `META_WHITE_VOID` только из-за префикса; тайные двери/мосты изнанки можно случайно найти по подсветке F в обычном мире; автономная Луна после метафинала только машет рукой, а не существует сама; событие на запуск дублируется; постмета ломает сейв; подарочные инструменты друзей раздаются Луне; Белая Пустота вновь сиреневый уютный остров; финал без безопасного ReturnAnchor.
