# 24 — Селекторы целей: одна геометрия для магии, поведения и правил (graybox 0.23)

**Статус:** [РЕАЛИЗОВАНО: СИСТЕМНЫЙ СРЕЗ]. Встроены детерминированные фильтры сущностей, применяемые движком правил и прямыми заклинаниями. Схема JSON совместима с сохранением. Полноценный визуальный редактор фильтров, ауры и мировые зоны ещё впереди.

## Философия

Игровой мир состоит из перекрывающихся свойств: категория `tree` остаётся древесной природой сущности, `CREATURE` — следствием её оживления, `PLANT`/`MACHINE` — роль, `NATURE`/`TECH` — теги, направленные отношения — социальный граф. **Селектор задаёт вопрос миру**, вместо отдельного сценарного условия для каждого объекта.

Все проверки действуют с первого запуска. Узнав законы, игрок сможет создавать неожиданно точные заклинания, правила и ловушки прямо на ранних уровнях — без отметки «знание открыто». Подсказки Луны могут постепенно объяснять селекторы, но не должны включать/отключать их серверную логику.

## Формат (TargetResolver)

Пример: найти до трёх ближайших оживлённых деревьев, принадлежащих растениям, на расстоянии не более 9 единиц:

```gdscript
{
    "radius": 9.0,
    "max_targets": 3,
    "category": "tree",
    "role": "PLANT",
    "tag": "NATURE",
    "alive": true
}
```

Фильтры применяются через AND, каждый необязателен кроме `radius`. Дополнительно: `attitude` — `FRIEND / HOSTILE / AFRAID / NEUTRAL` и `relation_direction` — `FROM_ORIGIN` или `TO_ORIGIN` (по умолчанию первое), `include_origin` — включить ли начальную сущность, если она удовлетворяет фильтрам. Значения ролей/тегов сохраняют свои технические имена на английском в обоих языках игры.

Системные ограничения: радиус от 0.5 до 12; от 1 до 8 целей (`max_targets`, по умолчанию 4). Отсутствующие, выгруженные и удалённые Entity не выбираются. Некорректные значения, неизвестные поля, `NaN` и бесконечность отвергаются. Результат упорядочен **сначала по расстоянию, затем по стабильному Entity ID**. Время создания Node и порядок компонентов сцен на результат не влияют.

## Применение в RuleEngine

Вместо `target: "EVENT_TARGET"` можно указать:

```gdscript
{
    "id": "luna:assist_plants",
    "owner_id": "fridge_001",
    "author_id": "luna",
    "event_type": "entity.target_acquired",
    "target": "SELECTOR",
    "selector_origin": "RULE_OWNER",
    "selector": {
        "radius": 8.0, "role": "PLANT",
        "alive": true, "max_targets": 2
    },
    "effects": [{"operation": "ADD", "parameter_id": "health", "value": 5}]
}
```

`selector_origin` выбирает `RULE_OWNER`, `EVENT_SOURCE` или `EVENT_TARGET`; если поле отсутствует, берётся владелец правила, а без него — источник события. Фильтр вычисляется в момент события, затем действия применяются через `EffectEngine.apply_to_selector`. Если найдено несколько целей, обычные изменения выполняются атомарно. Если одна — доступны также типизированные операции создания и удаления, при соблюдении ограничений раздела 23.

**Запрет обхода:** отдельные эффекты внутри правила-селектора не могут содержать `target_id`, переопределяющий отобранные системой цели. Правило с неверными полями не регистрируется.

## Применение в SpellService

Зарегистрированное прямое заклинание может содержать `target_selector`: тогда кликнутый объект становится центром фильтра, а действия выполняются на всех найденных целях одним атомарным batch.

```gdscript
{
    "id": "PLANT_MEDICINE",
    "label": "PLANT_MEDICINE",
    "cast_range": 20.0,
    "target_selector": {
        "radius": 9.0, "role": "PLANT",
        "tag": "NEEDS_HEALING", "max_targets": 2,
        "include_origin": true
    },
    "effects": [{"operation": "ADD", "parameter_id": "health", "value": 5}]
}
```

Текущая реализация не допускает сочетания `target_selector` с `BURST`/`CHAIN` или магическим `manifestation` — до появления единого двухфазного многообъектного планировщика. Эффект с выбранными `target_id` внутри селектора запрещён, иначе можно обойти ограничение. Заявленная цель недостижима — заклинание не проходит обычную проверку дальности; отсутствие подходящих объектов обрабатывается без изменения мира.

## Что теперь возможно

- Эффект действуют на **всех ближайших друзей** или **на ожившие растения**; одинаковая логика применима и к новому существу, и к оживлённому холодильнику, если у них подходящие роли и отношения.
- Правила способны искать союзников/врагов по направленным отношениям и реагировать на события без зашитых в скрипт названий видов.
- Сочетания ролей/тегов порождают неожиданные возможности, соответствующие философии «все правила мира честные и открыты».

## Долги

1. Выбор по различным радиусам и источникам в *одной многошаговой транзакции*; смешение нескольких жизненных циклов с эффектами на разные Entity.
2. Универсальные события касания/входа в зону, таймеры, использование предметов и ауры.
3. Селекторы по иерархии отношений, владельцам инвентаря, типам способностей и аспектам физики.
4. Удобный визуальный редактор селекторов в магическом конструкторе; описанный API уже работает до появления UI.
5. Отдельное пространство мира и портальные адреса: текущий селектор работает в одном запущенном мире и не просматривает другие.
