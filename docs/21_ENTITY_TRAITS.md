## Центральный инвариант

Оживлённое дерево всегда остаётся деревом:

- `record.category = "tree"` — **неизменяемая исходная категория**.
- `record.get_stored_roles() = ["PLANT"]` — исходные и добавленные роли.
- `IS_ALIVE: TRUE` → `record.get_roles()` дополнительно включает `CREATURE`, даже если у дерева нет лица или ног.
- `IS_ALIVE: FALSE` → вычисляемая роль `CREATURE` исчезает, но явные роли и исходная категория остаются.
- `record.get_tags()` — свободные безопасные метки, которые можно использовать для эффектов, поиска, сюжетных связей и будущего инвентаря.

Таким образом, роли **перекрываются**, а не заменяют категории. Живой холодильник может быть одновременно `MACHINE`, `OBJECT`, `CREATURE`; магический актёр может иметь `MAGICAL` и `CREATURE`; если игрок добавляет `TRADER`, он не превращается в отдельный физический тип.

## API

`EntityRecord`: `get_roles()`, `get_stored_roles()`, `get_tags()`, `has_role()`, `has_tag()`, `add_role()`, `remove_role()`, `add_tag()`, `remove_tag()`, `set_traits()`, `validate_trait_list()`.

`WorldRegistry.query_ids({"category":"tree", "role":"TRADER", "tag":"FRUIT_BEARING", "alive":true}, 16)` возвращает устойчиво отсортированные ID. Все фильтры необязательны и сочетаются через AND. Не более 24 результатов за вызов; невалидный запрос не выполняется. Это будущая общая база для фильтров заклинаний/магических правил/фракций/эмоций/открытий, вместо уникальных скриптов под каждый предмет.

## Значения и сохранения

- Роли/теги — строки в `UPPER_SNAKE_CASE`, до 32 символов, уникальные, максимум 24 каждого вида. Смена обоих наборов атомарна: недопустимая запись не меняет исходные коллекции.
- В `SaveService` сохраняются **только явно установленные роли**, а вычисляемый из `IS_ALIVE` статус восстанавливается автоматически.
- Копирование сущности создаёт независимый EntityRecord с копиями явных ролей/тегов, без изменения исходной категории.
- При загрузке JSON оба списка валидируются **до применения каких-либо изменений мира**.
- Старые сохранения без списков восстанавливают исходные роли и теги из категории. Не требуется новая версия общего файла мира.
- Это API уровня данных. Изменения ролей/тегов уже проходят через `CommandProcessor.execute_trait(target, operation, trait_name, initiator_id, source_id)` с командами `ADD_ROLE / REMOVE_ROLE / ADD_TAG / REMOVE_TAG`, собственным аудитом, Undo/Redo и событием `entity.traits_changed`. Внутриигровая панель редактирования и проверка игровых прав ещё впереди.
